# AC <-> Test Matrix - US-10.2: Pin the Node runtime and the undici override together

Every acceptance criterion of Story v2 (`AC-1` to `AC-15`, the Story's ids) is listed with the **kind of proof** and, where there is an automated test, the spec file and the exact `it()` title as written
in the file (copied from the source by grep, not retyped). The only spec file is `test/undici-pin.spec.ts` (runner: logic). Its sha256 and the red/green state are in the test generation report.

**Read this before citing the guard as proof.** `test/undici-pin.spec.ts` compares strings (files and runtime versions); it does not make a TLS call. It is therefore the **primary** proof only of the criteria that
are about the guard itself (AC-1, AC-2, AC-3, AC-5, AC-6, and the red half of AC-7). It is **supporting** coverage for AC-4, AC-8 and AC-9, whose primary proof is a recorded measurement or diff, and it proves
**nothing** about AC-10 to AC-15, which are recorded-evidence or gate rows and have **no automated test** (plan_review N-23: do not cite the guard as proof of a live behaviour).

Proof kinds: **A** automated guard case (primary); **A-support** automated, supporting only; **R** recorded evidence from a command or a live call, not an automated test; **G** gate / series result.

Rows whose cases are red today are red **by design** (TDD, AGENTS.md section 5): they turn green in T1 (the change set). State column is the state on the unchanged tree on `v24.22.2` (see the generation report).
