# AC <-> Test Matrix - US-10.4: Redesign the app shell

Every acceptance criterion of Story v4 (`AC-1` to `AC-9`, including `AC-4a`..`AC-4e` and `AC-6a`, the Story's own ids) mapped to the spec file and the test title that proves it. Titles are copied from the files as written. File names: **S** = `src/app/shell-nav.spec.ts` (logic), **W** = `src/app/app.component.shell-wiring.spec.ts` (logic), **C** = `src/app/app.component.shell.component.spec.ts` (components), **E** = `test/shell-evidence.spec.ts` (logic), **CA** = `src/app/app.component.clear-all.component.spec.ts` (components, adapted), **TW** = `src/app/app.component.template-wiring.spec.ts` (logic, adapted). "Green at" is the task that makes the row pass (the task breakdown's T-numbers); `P3` is the external evidence hand-off that no builder task can satisfy.

**What this matrix does not claim.** AC-5, AC-6 and AC-6a are **manual** criteria (Specification FR-13..FR-16, Out of scope: "Automated measurement of colour and layout"). No automated test asserts a rendered colour, a contrast ratio or a width. The rows below for them name the evidence file's sections and, for AC-5, the source-level token pins that guard only declaration and layering (not rendering). AC-9 is proved only to the extent that the record exists, is a registered artifact and has every required section (E); the substance of each measurement is the executor's.

Criteria marked partial: **AC-5** (source pins + manual), **AC-6** (manual only), **AC-6a** (manual only), **AC-9** (existence and structure only).
