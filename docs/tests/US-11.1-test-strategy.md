## What each level proves

- **Catalog (FR-1..FR-5, FR-10).** Whole-object equality for both Gemini 4 entries (id, label, tier, levels set and
  order, default level, 65536); exact order of the four text models, then the two image entries last; retired ids
  absent from the file, the browser view and the server view; the unchanged entries deep-equal their pre-Story
  values (characterization); `balanced` is the tier of Hydrogen and of nothing else. `clampLevel(gemini, M, minimal)`
  is `low` for Carbon, Hydrogen and 3.8 Flash on BOTH the browser and the server module, with catalog membership
  asserted before the clamp (the unknown-id fallback answers from the first Gemini model, so a clamp case without
  that guard is green for the wrong reason).
- **`balanced` in the type (FR-5).** A source scan counts `tier: 'premium' | 'balanced' | 'fast';` exactly twice and
  forbids `'premium' | 'fast'`. A compile-time assertion was tried and removed, see Deviations.
- **Server resolution (FR-19).** Table-driven over both retired ids and both tiers. Expectations for the fallback
  cases are derived from the catalog file, never written as a literal id the catalog swap would move.
- **Provider (FR-20..FR-23).** Faked SDK, whole-request key scan for `cachedContent`, `cachedContents`,
  `cached_content`, `temperature`, `topP`, `topK`, `top_p`, `top_k`; per-path caps (generate 65536, analyzeImage
  8000, extractFromPdf 8192, Specification v2 N-3); a fake `generateContentStream` that fails the call and records it,
  to prove nothing streams; CONTINUATION with real retry.
- **Pricing (FR-26..FR-29).** Exact objects at injected instants one millisecond before, exactly at and after
  `2026-12-01T00:00:00Z`; per-lookup evaluation observed by moving a fake clock across the boundary and back inside one
  module instance; cost for 1M tokens of each kind; source scan for the retired names (price literals such as 3.75
  do not match).
- **Settings service (FR-11..FR-18).** Restore tested per slot and per retired id (4 combinations), slot-provider and
  legacy top-level shapes, every level mapping, no level, persistence, second-restore silence (an instance spy on
  `localStorage.setItem`; a spy on `Storage.prototype` is blind to writes once a test has used `localStorage.setItem`
  in happy-dom), prototype-key ids, the Sonnet 4.6 migration in the same payload, defaults and reset.
- **Component (FR-6..FR-9, AC-4 UI).** Real `ModelSettingsService` (not mocked), queries by role and visible text,
  the badge found as the sibling of the model dropdown, class tokens read from the DOM.
- **Active docs (FR-30).** One case per file of the closed list so a failure names the file and line.

## Deviations from the task breakdown, with reasons

1. **FR-5 compile-time assertion removed.** The breakdown lists "lint: a `balanced` entry type-checks in both
   unions". A spec line typing a `'balanced'` value as the tier does fail `npm run lint` today, but the Angular
   `unit-test` builder type-checks every spec under `src/` in one program: the line stopped `npm run test:components`
   from building at all (observed: `TS2322` on the spec, 0 component specs ran). That would turn every component spec
   red for an unrelated reason. Also, `model-catalog.json` is cast through `unknown` in `model-catalog.ts`, so adding
   a `balanced` entry never fails tsc by itself. The source scan covers FR-5 at runtime instead.
2. **Fixture rewrites that are green now.** `test/call-log.spec.ts`, the two `test/image-studio/model-support.*`
   fixtures that name retired ids, and the `gemini-provider.spec.ts` retired-id fixtures are rewritten in this stage
   even where the breakdown schedules them with the task that would first turn them red, because each is a
   rewrite with no behavioural dependency. They are refactors of existing tests, recorded as such in the report.
3. **The "leaves minimal untouched on models that support it" test** (OD-8) is replaced by a `clampLevel` check on
   the models that remain, as the ruling allows.
4. **FR-30 recognition rule.** In the two files that exist to recognise retired ids, a retired name may appear only
   inside a declaration whose constant name contains `retired` or `remap`, on a table-entry line, or on a comment line
   that says retire, migrate or remap. This is a naming and wording convention for the builder, stated in the spec file
   header and in every failure message; it is not in the Specification.
5. **The installed SDK is read from `node_modules`.** FR-24 says "no 3.x installed". This case is red until the
   `npm install` of T1 has run, and stays valid for a fresh `npm ci`.
