# Test Strategy - US-10.2: Pin the Node runtime and the undici override together

## Scope and inputs

This Story is tooling and configuration (track server): `.nvmrc`, `package.json` (`engines`, `overrides.cheerio.undici`), `package-lock.json`, one README line and a set of recorded live checks. There is
exactly **one test file**: `test/undici-pin.spec.ts`, already in the repository from US-10.1 and **redesigned in place** here. Nothing under `src/`, `server/` or `tools/` is tested because nothing there changes
(NFR-7). The guard is written **before** any change to `package.json`, `.nvmrc` or `package-lock.json` (AGENTS.md section 5, spec FR-14) and left **red** on the unchanged tree.

Design authority: plan DD-1..DD-7 and spec FR-1..FR-9, FR-14. Where this file deviates from the plan's wording it says so (section "Deviations").

## The design (what the tests are built around)

1. **One pure decision, called by the real and the synthetic cases alike (DD-1).** Seven functions - `nvmrcPresent`, `nvmrcExact`, `enginesPresent`, `enginesExact`, `nvmrcEqualsEngines`,
   `runningNodeIsPinned`, `bundledUndiciEqualsPin` - take a plain `PinInputs` object and return `{ ok: true }` or `{ ok: false, cause, field, message }`. They read neither `process`, nor a file. The
   real case is `expectOk(fn(realInputs()))`; the synthetic cases are `expectCause(fn(good({...bad})), 'C#', '<field>')`. A non-vacuity proof therefore proves something about the real case.
2. **Lazy, non-throwing reads behind an injected `io` (DD-2).** `readTree(io)` returns `ok | missing | unreadable` per file; `realIo(root)` is bound to `UNDICI_PIN_ROOT` (resolved) else `process.cwd()`.
   Nothing reads at import time. A missing `.nvmrc`, `package.json` or lockfile fails ONE named case.
3. **Machine-readable causes (DD-3).** Each failing message starts with exactly one tag, `[C1]`..`[C5]` (C1 `.nvmrc`, C2 `engines.node`, C3 Running Node differs from `.nvmrc`, C4 Pin differs from the
   bundled undici, C5 `.nvmrc` differs from `engines.node`), names the file or field at fault, and contains no other tag. `expectCause` asserts the tag, the `field`, "exactly one tag" and "tag first"
   on every synthetic failure; the red record checks the same rule by script on the real messages.
4. **Normalisation (DD-4).** `.nvmrc`: `trim()` then at most one leading `v`, then `^\d+\.\d+\.\d+$`. `engines.node`: no normalisation. Offending content is quoted with non-printables (and `[`) escaped.
5. **No version is hard-coded (FR-8).** The pinned Node is read from `.nvmrc`; the Pin from `package.json`; the bundled undici from `process.versions['undici']`; the Running Node from `process.version`, all
   at call time inside the case. Version literals (`24.22.2`, `7.30.1`, `7.24.4`, ...) appear only as inputs of synthetic cases.
6. **The old window is gone and the removal is traced (DD-6).** The header carries a block headed `US-10.2 AMENDMENT (AGENTS.md 7.7: ...)`, in the shape of the US-9.1 precedent
   (`src/prompts/task-c.description-bytes.spec.ts`), saying what stopped being pinned, what is newly proven and what can no longer be shown. The window constants and checks do not exist.

## Deviations from the plan's wording

1. **`PinInputs` has more than five members.** DD-1 lists five (the `.nvmrc` text, `engines.node`, the Running Node, the bundled undici, the Pin). Two different "missing" messages for `engines` and
   `engines.node` (DD-5 S3) and a message that names `package.json` when it cannot be read need the whole `engines` value and a reason string, so `PinInputs` carries: `root` (label, message only), `nvmrc`,
   `nvmrcProblem?`, `pkgProblem?`, `engines` (the whole parsed value), `running`, `bundled`, `pin`. The purity rule (no `process`, no file, no clock) is unchanged.
2. **A missing or unreadable `package.json` or lockfile** fails the survivor cases and the runtime cases individually with a message naming the file (C2 for the engines cases, C4 for FR-7); DD-2 required
   the behaviour, not the exact wording.
3. **Case 5's "real field is read" proof** (`dependencies` lists `cheerio`) moved from a stand-alone non-vacuity case that read the real `package.json` at collection time into the real case 5 itself, so that
   no non-vacuity case depends on the tree. The assertion is kept, not dropped. The second case-5 non-vacuity case is now purely synthetic.
4. **The repository does not enable `strictNullChecks`**, so a discriminated union is not narrowed by `!v.ok`; a type guard `isFail` is used (found by `npx tsc --noEmit`).
