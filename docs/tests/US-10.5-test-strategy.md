## 2. What is deliberately not unit-tested, and why

- **CSS, contrast, 1024 px, slider pointer drag, the mismatched-size compare frame, truncation ellipsis.** happy-dom has no layout and Tailwind is not loaded in either runner. Covered by the class-level theme scan (T37) plus the manual evidence (section 7), as the plan decided (DD-15, S6). The compare slider spec asserts role, value, keys, labels and `object-contain`, not geometry.
- **The IndexedDB adapter itself.** No `fake-indexeddb` (recorded project decision). Compensated by the tested pair `toTurnRecord`/`fromTurnRecord` and the standing scan that the adapter calls only that pair (R-1).
- **The wire/usage label.** `server/` is untouched; the store specs assert the request body `presetId` (the wire value) is unchanged by an edit, which is what feeds the unchanged usage label.
- **`delivery.ts`, `zip.ts`, `output-format.ts`, `file-name.ts`**: UI-unreferenced after T21 but their specs are untouched (FR-6 Proposed); the delivery service specs prove the native path through them.
- **Coverage thresholds**: new `src/utils/**` helpers fall under the global floor and `prompt-presets.ts` under 95/95/85/95; the specs above exercise every branch of the pinned contracts. `QUALITY_GATE` measures it.

### Helper load order: what each shared helper loads, and when each module first exists (breakdown F-10; added in v3 after the T19 loop-back)

A module owned by a later task is loaded only on a code path that a spec of that later task (or later) takes. Found by the builder at T19: `service-setup.ts` loaded `studio-delivery.service` (T20) unconditionally, so all 11 cases of the T19 spec `studio-media.service.spec.ts` failed with `ERR_MODULE_NOT_FOUND` before reaching an assertion. No assertion was changed; the media spec changed only its helper call.

## 8. Regex rule for non-ASCII (Cyrillic) text (added in v4 after the T26 loop-back)

**Finding (builder, T26; a test defect, `changes_required_tests`).** In `src/app/components/image-studio/studio-empty-state/studio-empty-state.component.spec.ts` the case "under uk the cards carry the Ukrainian names and descriptions" asserted `/^Товар на білому тлі\b.*Ідеально для товарних карток/` (and the same shape for "Лайфстайл-сцена" and "Банер категорії"). In JavaScript, `\b` without the `u` flag is ASCII-only: it is a boundary between an ASCII word character (`[A-Za-z0-9_]`) and anything else, and every Cyrillic letter counts as "not a word character". After a Cyrillic last letter followed by a space there is no boundary, so the pattern was unsatisfiable for any accessible name of the form "<name> <description>" (the component renders `aria-label` = name + " " + description). Verified in node: the old regex tested against 'Товар на білому тлі Ідеально для товарних карток' is `false`; it is `true` only for "...тлі1 Ідеально...". The English twins (`Product on white\b`) were fine because the last letter is ASCII, which is why the defect did not show in the en case.

**Fix.** `\b` replaced by the lookahead `(?=\s)`: `/^Товар на білому тлі(?=\s).*Ідеально для товарних карток/` and the two siblings. The assertion pins the same facts as before: the Ukrainian name FIRST (anchored at `^`), a whitespace separator right after it, then the Ukrainian description later in the string. Nothing was loosened.

**Rule (binds every spec of this Story and any later one).** A regex applied to Cyrillic (or any non-ASCII) text must not use `\b`, `\B`, `\w`, `\W` or `[a-z]`/`[A-Z]` to mean "word", "letter" or "boundary": they see only ASCII (`\b` and `\w` stay ASCII even with the `u` flag). Use `(?=\s)`, `(?=$)`, `(?![\p{L}\p{N}])` with the `u` flag, `\s`, an explicit literal, or `toContain`/`toBe`. `\b` stays allowed where both neighbouring characters are ASCII by construction (`\bv1\b`, `\bseconds?\b`, `\b1 image\b`). Case-insensitive `/i` on Cyrillic works (simple case folding) and is allowed.

**Node check of the corrected regexes** (names "Товар на білому тлі", "Лайфстайл-сцена", "Банер категорії"; descriptions "Ідеально для товарних карток", "Товар у реалістичному оточенні", "Широкий формат із місцем для тексту"): each card regex is `true` for "<name> <description>" of its own card and `false` for the wrong order, name only, description only, name glued to the description, name followed by a non-space character, the right name with another card's description, and another card's name with this card's description. The old `\b` regex is `false` for the correct string. Output: test generation report v4, section "Revision v4".

**Scan of the other specs of this Story** (all `*.spec.ts` changed since the merge base with `main`, plus a repository-wide grep of `*.spec.ts`): every line holding both Cyrillic text and `\b`/`\B`/`\w`/`\W`/`[a-z]`/`[A-Z]`; every `\b` adjacent to an interpolated `${...}`. Result: the three lines above were the only defect. All other `\b` uses in Story specs match ASCII text (`\bv1\b`, `\bv\d+\b`, `\bseconds?\b`, `\b1 image\b`, the ASCII wording regexes of the translate/simplified specs); the Cyrillic regexes elsewhere (`/Орієнтовна вартість/`, `/imageStudio:\s*'Студія зображень'/`, `/below|нижче/i`, `/1[.,]75\s(?:mm|мм)/`) use literals and `\s` only. The one remaining hit (`src/utils/tov-second-person.spec.ts` line 28) is a comment quoting a naive `/\bви\b/` as the bug it avoids, in a spec this Story did not change.

## 9. Assertion scope: a query must not see content the fact does not own (added in v5 after the T28 loop-back)

**Finding (builder, T28; a test defect, `changes_required_tests`).** In `studio-turn-card.component.spec.ts`, case "FR-3 (a): input thumbnails (T28) > renders one thumbnail per resolvable reference with the alt "Input image {n}" - never the prompt - and none inside a figure", the last assertion was `expect(within(article()).queryByAltText('prompt 1')).toBeNull()`. The facts before it (thumbnail alts exactly `['Input image 1','Input image 2']`, none inside a figure) were right and passed.

**Rule (binds every spec of this Story and any later one).**
1. **A negation, a count or a whole-container `getBy` / `queryBy` / `getAllBy` must be scoped to the element the FACT is about.** "Never the prompt" is a fact about the input thumbnails, not about the card. Before writing `within(<container>).queryBy...`, `.not.toMatch` or `toHaveLength(n)`, list what else lives inside `<container>` by the DOM contract (section 3 and the header of `test/image-studio/helpers/studio-render.ts`): the generated tile (`<figure>`, img alt = prompt, caption `v{N}`, buttons Download / Edit this -> / Compare with v{n}, chip "Edit of v{n}"), the strip thumbnails (a `<button>` holding an `<img>` alt = prompt), the dialog, the status region ("Version v{N} is ready"), the text parts, the input thumbnails. 2. **Do not loosen the fact to make the scope fit.** The corrected check keeps all three facts (the exact thumbnail alts, none inside a figure, none carrying the prompt) and does NOT require the tile to drop its prompt alt.
3. **A match must not be satisfiable by an unrelated descendant.** A positive lookup such as `getAllByText(/\bv2\b/).length > 0` is vacuous when another element (the status region) prints the same text.
4. **A "stays the same" count needs a precondition.** `before === after` passes at `0 === 0`; assert that `before` is the expected positive number first.
5. **An absence that holds only because the element is not built yet needs a positive twin that is red until its owner task.** Either a sibling case that finds the element, or (preferred) a precondition inside the same case that finds it first and then watches it disappear, so absence is proved against something demonstrably there.
6. **A sequence-end check on a container that has later siblings is vacuous.** `not.toMatch(/·\s*$/)` on a card whose summary line is followed by tiles looks at the tile's last button, not at the summary.

## 10. Query names follow the render language: a helper must not hard-wire one language (added in v6 after the T30 loop-back)

**Finding (builder, T30; a test defect, `changes_required_tests`).** In `studio-feed.component.spec.ts` the helper `log()` was `screen.getByRole('log', { name: t('X-26', 'en') })`, i.e. the English name "Conversation". **The inputRefs cap: 10, and its source.** The app's real maximum number of image parts in one user message is **6**: `MAX_UPLOADS = 5` user uploads (`src/utils/image-studio/upload-rules.ts`, US-10.1 FR-10, enforced by `canAttachUpload` / `countUploads`) plus the single attached earlier version, which is outside the five (`upload-rules.ts`: "the attached version is outside the five"; one `attachedVersion` per draft in `image-studio.store.ts`). `inputRefs` is derived from exactly those parts of the sent user turn (`deriveInputRefs` in `src/utils/image-studio/apply-response.ts`: every part with `fileData` or `inlineData`). `src/prompt-core/image-studio-contract.json` carries no attachment limit (searched). The cap must be >= 6 so no genuine record is truncated, and the human bounded it at <= 20 ("10-20"); **10** leaves head-room of four over the real maximum and is the lowest value of the human's range. The tests use the literal 10.

**Open design choice left to the builder (not pinned, stated so it is not a surprise).** The Security Review's wording for NB-3 was "skipped from the delivery items". The tests do not pin whether the unresolvable version stays in `items()` with `mime: null` (the existing shape for a version whose bytes are gone, and the one the tile, strip and numbering rely on) or is left out of the list: every `items()` case asserts only that no item carries the stored MIME and that the valid neighbours (v2 jpeg, v3 webp) are intact, via `find(...)?.mime ?? null`, which holds under both. Likewise `data` of the rejected item is not pinned (and the tile's caption for an NB-3 image is not pinned). The cases that observe delivery (`download`, `copy`, `downloadAll`) hold under both. A mixed `downloadAll` (one rejected version among valid ones: X-22 for the whole archive versus a zip of the valid ones) is deliberately NOT pinned.

## 12. DD-15 amendment: the amber Retry label meets 4.5:1 (added in v8 after the T42 manual evidence, check C-4)

**Source of the decision.** `docs/evidence/US-10.5-image-studio-redesign-manual-verification-evidence.md` v1, check C-4 (Chrome 156, 1024 px, 2026-11-09): the composer's attachment "Retry" label (`studio-composer.component.html` line 79, `bg-amber-600 text-white text-[10px] font-semibold`) measured white on `#d97706` = **3.19:1** in both themes, below the 4.5:1 WCAG 2.x AA rule of FR-30 (all studio text). Plan DD-15 had exempted `bg-amber-600 text-white` from the `--shell-*` colour rule; the exemption covers the colour family, not contrast. The human decided (verbatim): "замінити bg-amber-600 на bg-amber-700 (білий на #b45309 ≈ 5,0:1) і прибрати зі списку винятків DD-15 амбровий підклад. Це зміна одного класу в шаблоні композера, з тестами спочатку (теорія сканування теми має це перевіряти), в окремому коміті."
