# Implementation plan: US-10.5 - Restyle Image Studio to the new design, without new capabilities (v2)

Track: `angular` (primary). Every change is under `src/app/components/image-studio/**`, `src/services/image-studio/**`, `src/utils/image-studio/**` and `src/prompt-core/prompt-presets.ts`. No `server/` file, no `src/domain/` schema, no prompt, no renderer, no validator, no FROZEN file, no `index.html`, no `src/styles.css` and no `STORE_REGISTRY` value is touched.

This version supersedes v1, which was built on Specification v3's alternatives and Impact Analysis v1. The Specification (v4) is `APPROVED` by the human including every Proposed block (so FR-13 / OD-27 and FR-23 / OD-28 are ratified text here). The owner rulings SQ-1-B, SQ-2-A, SQ-3-A, SQ-4-i, SQ-5-B, SQ-6-A + SQ-6-U1, SQ-7-A are base requirements: the option scaffolding of v1 section 1 (OI-1, OI-2, OI-3a, OI-3b) is gone and each ruled seam is designed to the ruled behaviour. The impact analysis (v2) is consumed, not re-derived; where this plan reads source it is to fix a design point the survey left open.

## 1. Open items for HUMAN_PLAN_APPROVAL

The ruled points are closed. Two points remain where the approved Specification is silent. This plan does not choose either. Each is isolated behind one named seam, so either ruling is a bounded change. **Neither makes the plan unfinishable:** the plan can be written, reviewed and broken into tasks with both unresolved; what they gate is the tests that exercise the seam (named below). Both are non-blocking Open Decision candidates (`open_decisions_blocking: false`). Whichever option the human picks should be written into the Specification before TEST_WRITING so the tests and the reconciliation review check the ruled text; an option that contradicts an existing FR would be a loop back to SPECIFICATION, but none of the listed options does.

### OI-A (impact S12 and U-9): what is "the last prompt entered in that session" after an images-only or a chip send

Facts (from source). `Version.prompt` is `buildInput.text ?? ''` (`image-studio.store.ts` L438) and `send()` passes `draft.text`, so an images-only send (kept by SQ-1-B) stores a **blank** version prompt. `sendChip()` sets the draft text to the English chip instruction, so a chip send stores that instruction as the prompt. FR-2 defines the row name as "the last prompt entered in that session" and FR-12 defines `sessionName` as "the same value as the session name in FR-2" with the fallback `{timestamp}-image-studio-versions.zip` when K is empty. The Specification does not say what "the last prompt" is when the latest version has a blank (images-only) or a chip prompt. A text-only reply, a safety block and a failure store no turn and no version, so they never supply a prompt.

Seam: one pure function `sessionName(meta: { versions: Version[] }): string` in new `src/utils/image-studio/session-name.ts`, the only place that decides. The session-list row and `buildArchiveName` both call it, so FR-2 and FR-12 cannot drift. Whitespace is collapsed and the value is trimmed inside it; it is not cut by `buildAlt`.

| Option | `sessionName()` returns | Row / archive after an images-only latest send | After a chip latest send | Cost |
|---|---|---|---|---|
| a | the prompt of the retained version with the highest number, even if blank | no row name; archive `{timestamp}-image-studio-versions.zip` | the chip instruction (for example `remove-the-background`) | none (literal reading) |
| b | the prompt of the highest-numbered retained version whose prompt is not blank | the last typed prompt | the chip instruction | none |
| c | a text field the store maintains for the last user-typed (non-chip, non-blank) text | the last typed prompt | the last typed prompt | adds a stored field (`SessionMeta`, optional) and the adapter / schema / fake change for it |

Gated: the row-name and archive-name specs for the "latest version is images-only" and "latest version is a chip send" fixtures. Not gated: every vector with a non-blank latest prompt (the five FR-12 vectors, the transliteration table, the cut rule), the row layout, the date and cost.

### OI-B: does "Reuse prompt" count as an edit for the check mark and the wire `presetId`

FR-14 clears the check mark "as soon as the user edits the prompt text" and keeps the sent `presetId` apart from it. FR-5 (Proposed, approved) says the restored prompt replaces what was in the field. Neither says whether this programmatic replacement is an "edit" for the check mark, nor whether a `presetId` left in the draft by an earlier pick (the wire value) is still sent with the reused prompt. Seam: the single `presetPatch` object inside `store.reusePrompt()` (DD-11); nothing else reads the choice.

| Option | check mark after Reuse | wire `presetId` after Reuse | Visible effect |
|---|---|---|---|
| 1 | cleared | kept (as after a typed edit, SQ-2-A) | no chip on the stored turn; the usage `taskLabel` still carries the earlier pick |
| 2 | cleared | cleared | no chip; the usage `taskLabel` has no preset |
| 3 | kept | kept | the check mark can show on a preset whose template the restored text does not match; a stored chip appears |

Gated: the `reusePrompt` cases of the store spec and the "Reuse prompt" component spec rows about presets. Not gated: Reuse's text, ratio, model, resolution fix-up, focus and "sends nothing" rules (FR-5).

### Non-blocking findings carried to the human (not open items; the plan has designed to the text)

- **F-1 (impact U-11, designed, confirm).** The cross-session seed (`switchModel`, blocked-state `editVersion`) cannot produce a source version, because the stored source is recorded only when the attached version names a version of the *current* session (DD-5). This is FR-9's own sentence "an image of a session's first generation (no earlier version exists)" stores none; the plan states it as a predicate so a multi-image first generation cannot get an "Edit of v1" pointing at its own sibling image. The human should confirm this reading covers the cross-session case.
- **F-2 (impact U-9).** After a chip send the session name is the English chip instruction under options a and b of OI-A. This is surfaced here so it is not a surprise.
- **F-3 (impact U-12, disposition wording).** D-1 says "the send-button lookups use the name Generate"; ten existing sites need the "Write a prompt to start" label or a label-independent query (DD-17). FR-32 (a) permits it. The implementation report's changed-spec list must name them.
- **F-4 (D-8 "same alert").** Under native delivery a conversion failure no longer exists; "the same alert" (X-21) is reachable only through the injectable archive builder (DD-6). The plan provides that seam; if the human reads "same alert" more loosely (any alert), the seam is still harmless.
- **F-5.** An orphan first user turn whose model turn was cut is not shown by the card feed (R-6), where the old log showed it as a bubble.
- **F-6 (accessibility name of the preset input thumbnails).** Input thumbnails need an `alt` text that is not the prompt, otherwise the L394-395 tile count would also match them; a new text id is allocated (DD-7).

## 2. Approach

Image Studio keeps its one root store (`ImageStudioStore`), its ports and its pure `utils/image-studio` modules. The change has four parts.

1. **A pure view model.** A new pure module `src/utils/image-studio/feed.ts` turns a `StoredSession` into the results feed: one card per stored model turn (cards are anchored on the turn that holds the images), each with its prompt, ratio / resolution / model, preset, summary values, ordered text and image items, thumbnail references and the edit-source information of each image. It decides the main image (highest retained version number) and so where the one strip goes. All validity rules of FR-23 live in readers in `schemas.ts` that the feed builder applies on every build.
2. **A thin stored-shape extension.** The model turn gains `cost`, `durationMs`, `presetId` and `inputRefs`; the `Version` gains `editOfVersion`. All optional, omitted when unknown, never rewritten into old sessions. The three silent-loss paths found by the survey (IndexedDB adapter, generate request, schema layer) are closed by design.
3. **A component tree split by responsibility.** Today the version strip owns all delivery state. That state moves to a container-scoped `StudioDeliveryService`; the full-view dialog becomes its own component hosting the new compare slider; the feed, turn card, image tile, header and empty state are new components. All are standalone, `OnPush`, signal-based and `inject()`-based. No RxJS.
4. **Pure helpers for every text, date, name and count the new UI needs**, written without `Date`, with plural categories from the CLDR rule, so they are testable in the logic runner without a time zone.

Native, one-click download delivers the bytes the studio holds, untouched, with the extension of their MIME (DD-8). The three owner departures are plain consequences: the selector is removed from the dialog, the archive is named by a pure function of the session name and the instant, and the studio markup uses only the existing `--shell-*` family. The ruled behaviours are implemented in the store and composer (sendState, two preset fields, duration, edit source) with no change to the request body, the wire or the usage label.

## 3. Design decisions

### DD-1 Domain model: where the new fields live (FR-23, FR-3, FR-4, FR-9; impact S1)

The studio schemas live in `src/utils/image-studio/` (not `src/domain/`); `ProductDescriptionDoc`, `ConsumablesDoc` and `test/fixtures/corpus/**` are not reached. `SessionMeta.schemaVersion` stays `1`: every addition is optional on read, so no migration is needed and an older build still reads newer sessions (stored records pass unknown keys through).

- On the **model turn** of a generation (the turn that holds the images and that `Version.turnId` points to): `cost?: number` (USD of the response, the same number `applyResponse` adds to `meta.costUsd`), `durationMs?: number`, `presetId?: string` (the recorded value, DD-5), `inputRefs?: Array<{ turnId: string; partIndex: number }>`.
- On the **`Version`**: `editOfVersion?: number` (FR-9 is per image, `Version` already survives through `put(batch.meta)`, and the validity rule is relative to the image's own number).

Reasons for the model turn: the card, the images and the versions are all keyed by it, so a cut that removes the user turn leaves a card that still renders (prompt and ratio come from the versions); only the thumbnails then degrade, through the dangling-reference rule. The user turn stays exactly the resend payload it is documented to be.

`inputRefs` point at image parts (`fileData` or `inlineData`) of the user turn that was sent with the generation, by `(turnId, partIndex)`. An index reference survives `remapFileUris()` (it rewrites `fileUri` inside the part, not the position), so a FILE_MISSING recovery cannot make a reference dangle (impact S2). `inlineData` parts (attached version) carry their bytes; `fileData` parts (uploads) are read by `SessionStorePort.getSentBytes(sessionId, fileUri)` through the media service (DD-9); missing bytes omit the thumbnail without error (FR-3).

Types: `Turn` and `Version` in `ports.ts` gain the optional members with a doc comment that the new `Turn` members are display metadata and are **not** part of the resend payload (DD-4). `apply-response.ts` `ApplyContext` gains optional `durationMs`, `presetId`, `editOfVersion`, `inputRefs`; the new keys are written only when defined (never `undefined`), so the existing `apply-response.spec.ts` full-`Version` `toEqual` (L107) and the stored records of old sessions keep their shape.

Old sessions (FR-25, NFR-6): nothing is rewritten. Absence is the old-session representation.

### DD-2 Read-side validity and the feed builder (FR-23 table = ratified OD-28, FR-3, FR-4, FR-9, FR-25; impact S5)

`parseStoredSession` / `parseStoredTurn` keep returning `null` only for core-field failures (P-9 unchanged) and the new fields are **not** added to their zod objects, so a malformed optional field cannot make a session vanish from the list. Validation is done by pure readers exported from `schemas.ts` and called by `buildFeed()` on every build:

- `readTurnExtras(turn)` returns `{ cost?, durationMs?, presetId?, inputRefs? }`: `cost` / `durationMs` kept only if a finite number >= 0; `presetId` kept only if a non-empty string (registry membership is checked by `buildFeed` through an injected predicate so `utils/image-studio` does not import the registry); `inputRefs` kept entry by entry, an entry kept only with a string `turnId` and a non-negative integer `partIndex`.
- `readEditSource(version, versions)` returns the source number only if an integer >= 1 and strictly lower than `version.number`, and reports separately whether that source still exists in `versions` (chip stays, Compare hidden when it is gone, FR-9 Proposed).
- Dangling `inputRefs` (turn missing, part missing or not an image part) are dropped one by one.

Doing validation at read time, not parse time, is deliberate: the on-disk record is never normalised (NFR-6), and the in-memory test fakes bypass `parseStored*`. This answers impact S5 and the "present but invalid" table, which needs its own seeded sessions at TEST_WRITING.

`buildFeed(session, deps)` returns `{ cards: FeedCard[]; mainVersionNumber: number | null }`. A `FeedCard` holds: `key` (model turn id), `prompt` (first version's `prompt`, trimmed; empty means no Reuse button), `aspectRatio`, `resolution`, `model` (from the card's versions), `presetId` (validated and known), `thumbs` (validated refs), `summary: { count; cost?; durationMs? }` (`count` = versions of that turn; text parts never add to it, FR-3 rule 2), `items` (ordered text and image items, DD-7), `images` (per version: number, part index, `editOf?: { n; sourceRetained }`), and `holdsMain`. The main image is the retained version with the highest number (ratified FR-13 item 1). User turns without a following stored model turn produce no card (R-6).

### DD-3 Persistence adapter: closing the silent drop (impact S1; FR-23 "the save path does not drop them")

`IndexedDbSessionStore.turnRecord()` and `loadSession()` copy only `id, role, parts`. No spec covers the adapter and the project decision is not to add `fake-indexeddb` (recorded in `fakes.ts`). Design: extract the row mapping into a pure pair in new `src/utils/image-studio/turn-record.ts`: `toTurnRecord(sessionId, turn)` (spreads the whole turn, including every optional field) and `fromTurnRecord(row)` (drops only `sessionId`; passes the rest through `parseStoredTurn`). The adapter calls the pair at its two sites; `remapFileUris` keeps its `{ ...row, parts }` spread (already field-preserving). Validation: a logic-runner round-trip spec on the pair (fields survive; an old row without the fields reads back identical), plus a standing source scan added to `test/image-studio-architecture.spec.ts` that the adapter source contains both helper calls and no other construction of a turn row (added, not weakening any scan).

### DD-4 Resend payload: the new fields stay out of the request (impact S3; FR-23, FR-17 rule 5)

`buildGenerateRequest()` clones whole stored turns into `history`. It is changed to project each stored turn to `{ id, role, parts }` (a helper `toResendTurn()` in `request-builder.ts`) before cloning. A turn without extras is unchanged, so `request-builder.spec.ts` L64 (`request.history` `toEqual(before.turns)`) stays green; a new spec seeds a turn with every extra and asserts the request equals the projection. The server schema (`turnSchema`, not `.passthrough()`) would strip the keys anyway, so no server change and no wire-contract change (NFR-1); the projection keeps the request size and "a turn is the resend payload" true. No field is placed inside a `Part` (`partSchema` is `.passthrough()` and parts reach the provider). `request-builder.ts` is not FROZEN.

### DD-5 Measuring and recording (FR-24 ruled, FR-9 ruled, FR-14 ruled; impact U-6, U-11)

All in `ImageStudioStore` and `applyResponse`:

- **Duration (SQ-6-A + SQ-6-U1).** `execute()` reads `startedAt = clock.now()` as its first statement and passes it through `applyOutcome` to `commitResponse`. `send()` and `retry()` both enter `execute()`, so Retry restarts the clock (FR-24). In `commitResponse`, `applyResponse` is synchronous and `await this.port.commit(...)` follows with no `await` in between, so the value `now = this.clock.now()` already read for `ctx.now` is the hand-off instant. The plan reads the clock **once** there (`const now = this.clock.now()`), passes it as `ctx.now`, and sets `ctx.durationMs = Math.max(0, now - startedAt)`. The batch write and the attachment upload are not in the interval, as ruled; the "including the wait for upload" clause no longer exists in the text and nothing is built for it. The `loadValid()` read before `applyResponse` is inside the interval. There is no residual shortfall to flag.
- **Cost.** `cost = response.costUsd` on the model turn: the same number `applyResponse` adds to `meta.costUsd` (FR-24 Proposed, ratified). A response that stores no turn (text, safety, failure) writes neither field because `applyResponse` returns no batch.
- **Edit source (SQ-7-A) and the cross-session seed (impact U-11).** `editOfVersion` is recorded for the images of a generation **iff** the send-time draft carried an attached version **and** `draft.attachedVersion.fromVersion` names a version already present in the current session's `meta.versions` (read from `stored` before `applyResponse`). A quick-edit chip send (no attached version) and a typed follow-up record none; so does the detach-before-send case, because the snapshot taken at send holds no attached version (FR-9 Proposed, ratified). The second clause is FR-9's own text: "an image of a session's first generation (no earlier version exists)" has no source. It also closes U-11: `switchModel` and the blocked-state `editVersion` both call `createSession({ seed })`, putting `fromVersion` of the *previous* session into the first draft of a *new*, empty session; the new session holds no version, so the predicate is false and nothing is stored. Without the clause a multi-image first generation (several images in one response) would be given `editOfVersion = 1` and its second image would show "Edit of v1" pointing at its own sibling image, with a Compare to it; the read-side validity rule (source strictly lower than the image's own number) would not catch that. Finding F-1.
- **Input refs.** Computed in `applyResponse` from `ctx.userTurn.parts` (indexes of `fileData` / `inlineData` parts).
- **Preset (SQ-2-A).** The recorded value is `draft.checkedPresetId` (the preset whose check mark was showing at send), written to the model turn only when non-null. The wire value is `draft.presetId` and is read by `send()` for `BuildInput.presetId` exactly as today.

    [row outside the log]     Download all (N) .zip, SynthID notice (not rendered while the empty state shows)

- The container keeps: the single `role="status"` region, the `role="alert"` region, the focus-return effect (FR-33), `setLanguage`, `init`.
- `StudioDeliveryService` (new, `src/services/image-studio/studio-delivery.service.ts`, provided on the container so its state dies with the page, not root): owns what `StudioVersionStripComponent` owns privately today and nothing new: the `items` computed (versions with their bytes), `busy`, `messageId`, the open full-view state (`{ number, compareWith? } | null`) and the opener element for focus return, and the actions `download`, `copy`, `edit`, `downloadAll`, `open`, `close`. The failure mapping (`X-18..X-22`), `markDownloaded` after success and busy gating move unchanged. Download all is disabled iff `items().length === 0 || busy()` (SD-28, FR-11); generation does not disable it.

### DD-7 Feed, container, text parts, main image, strip placement, empty state and progress (FR-3, FR-13 ratified, FR-18, FR-20, FR-33; SQ-3-A, SQ-4-i)

- **Container (FR-3 (h)).** `app-studio-feed` renders `<div role="log" aria-live="off" [attr.aria-label]="X-26">` always (as today). It holds the cards, the single strip, the events, Retry, and the empty state or first-generation progress. The Download-all row and the SynthID notice are controls and a note, so they sit above the log element, not inside it. The full-view dialog is a sibling of the feed outside the log (no dialog inside a log container; the dialog's prompt-alt image stays out of `within(log)` counts, impact S7).
- **Tile scoping hook.** Each image tile is a `<figure>` labelled by its `<figcaption>` (`aria-labelledby`). Only tile images are `img` elements inside a `figure`. Strip thumbnails (alt = prompt) sit in `button`s in the strip list, never in a `figure`; input thumbnails (FR-3 (a)) are not in a `figure` and use a new text id as `alt` ("Input image {n}" / UA form, never the prompt). This gives the L394-395 narrowing something to select: images of the log whose closest ancestor is a `figure` (the expected count stays 2).
- **Text items (SQ-3-A).** `buildFeed` returns per card `items: Array<{ kind: 'text'; text } | { kind: 'image'; versionNumber }>` in API part order (thought parts and blank text excluded, as the current `log` computed does). The card template renders text items as a restyled model-text paragraph between the tiles, in that order. Rules 1-4 of FR-3: tile order is API order; text parts add no image, version or unit to the summary `count`; they raise no error and never change the strip's listing; every tile appears once.
- **Strip placement (FR-13 ratified).** The feed iterates `buildFeed().cards` oldest first. Directly after the card with `holdsMain` (the card of the highest retained version) it renders the single `<app-studio-version-strip>`; it is not inside any card, so the card tiles and the strip never mix. It follows the card, so it precedes events and Retry (any feed entry after that card). With no retained version there is no card and no strip. If the main card is absent (its turn was dropped) the strip is rendered at the end of the feed. A trailing model text part of the main card sits between the last tile and the strip; FR-13 requires only that the strip follows the tile and precedes entries after the card.
- Non-history events (`store.events()`, text replies) and Retry keep their content and behaviour, restyled, after the cards (FR-3 Proposed).
- **Empty state** shows iff `currentSession().turns.length === 0 && !store.generating()` (FR-18). **Progress** shows instead iff the same turn condition holds and `store.generating()`. The progress element is presentational: `aria-hidden="true"`, no `role`, no `aria-live` (FR-20, FR-33; impact S7: the existing assertion counts `[role="status"]` and `aria-live="polite"`). If the first generation fails and stores no turn, the empty state returns. Before any session exists the log renders empty.
- **Starter cards.** `STARTER_PRESET_IDS = ['white-bg', 'lifestyle', 'banner']` exported from `prompt-presets.ts`; the cards are `STARTER_PRESET_IDS.map(findPreset)` showing `presetName` and `presetDescription` (a preset without a description renders no element). Choosing a card calls `store.applyPreset(preset)`, the same function the preset row calls (DD-11), so FR-19 and impact S13 hold by construction. Cards are buttons whose accessible name is the preset name plus description or are named so that the composer's preset row lookup `getByRole('button', { name: <preset name> })` is not duplicated (R-9): the card's name is the preset name followed by its description, so an exact-name lookup finds only the row button.

### DD-8 Native download, Download all and the archive name (FR-6, FR-11, FR-12; impact S10, U-8; SQ-5-B)

- **Native format** is the MIME the studio holds (`item.mime`, the API bytes), not `Version.inputFormat`. The service passes `targetMime = item.mime` to `deliver()` and `buildZip()`, which return the bytes untouched when source and target match (`delivery.ts` L52), and `buildFileName` derives the extension from the delivered MIME (the `1x1` in `image_v1_1x1.png` is the aspect ratio, not a probe). ### DD-9 Render-time size and thumbnails (FR-7, FR-3; impact S8)

`StudioMediaService.sizeOf(key, getBytes)` returns a signal holding `{ width, height } | null`, keyed by `turnId:partIndex`. The first request calls `ImageCodec.probe` once and keeps the result in a `Map`; a rejection stores `null`, is never retried or surfaced (label degrades to `v{N}`); re-renders reuse the entry, so for N distinct images the probe is called N times whatever the number of feed re-renders. ### DD-13 Dates, time zones and the `Date` ban (NFR-4; impact S9, U-10, scan g)

`new Date(` and `Date.now` are banned in `src/utils/image-studio`, and a time zone cannot be set in either runner. Design:

- `formatRowDate(epochMs, offsetMinutes)` in `src/utils/image-studio/format.ts` computes `dd.MM · HH:mm` by integer arithmetic from the epoch and an explicit offset; `buildArchiveName` computes UTC the same way. Neither touches `Date`.
- The offset comes through a new port `LocalOffset { offsetMinutes(epochMs: number): number }` (type in `ports.ts`, token `LOCAL_OFFSET_PORT` in `image-studio.tokens.ts`, browser adapter in `browser-ports.ts` using `-new Date(epochMs).getTimezoneOffset()`, the only place `Date` is constructed; `browser-ports.ts` is outside the scanned directory). Tests provide a fake with a fixed offset, so no `TZ` variable and no wall clock is involved ("the controlled time zone" of NFR-4). Per-instant offsets keep daylight saving correct in production.
- Summary seconds use `toFixed(1)` on `durationMs / 1000`; cost uses `$` and `toFixed(2)`, both in `format.ts` with the partial-field rule of FR-4 (a missing segment drops its separator; a missing or invalid value is never `NaN`, `undefined` or `$0.00`).

## 10. Rejected alternatives

- **Compute the dimensions once at generation and store them** - rejected by the Story (AC-4, FR-7): not stored, computed at render.
- **Put `cost`, `durationMs`, `presetId` on the `Version` or `SessionMeta`** (survives `put(meta)`, no adapter change, no resend leak) - rejected because the owner placed the first three on `Turn` and the Specification follows; the cost is handled by DD-3 / DD-4 instead.
- **Put the Turn fields on the user turn** - rejected: the card, the images and the versions are anchored on the model turn, and a cut of the user turn would lose the summary and chip along with the thumbnails.
- **Derive thumbnails from the paired user turn without stored refs** - rejected: FR-23 requires stored references, and the pairing is not guaranteed after a cut.
- **Validate the new fields in the zod schemas** - rejected (S5): a failure returns `null` and hides the whole session; fakes bypass parsing.
- **Add `fake-indexeddb` to test the adapter** - rejected: a recorded project decision; the pure-mapping extraction gives the same protection.
- **Reuse `slug-utils.transliterateCyrillic` for the archive name** - rejected: a different scheme; editing it would move the content-slug pipeline.
- **Derive the starter cards as "presets that have a description"** - rejected: adding a description to `social` would silently add a fourth card; an explicit `STARTER_PRESET_IDS` is used.
- **Keep delivery state inside the strip and pass it to the feed by outputs** - rejected: Download, Edit, Download all, Compare and the dialog all move to different components; a container-scoped service keeps one `busy`.
- **Keep the format conversion path alive for Download by `inputFormat`** - rejected: "native format, no choice" is FR-6; D-6 / D-7 pin native delivery.
- **A `Date`-based local formatter in `utils/image-studio`** - rejected: scan g; the injected offset port is testable without `TZ`.
- **Edit `index.html` to add shell tokens** - rejected: no studio need exceeds the eight tokens (DD-15).
- **A second `role="status"` for the first-generation skeleton** - rejected (FR-20, FR-33).
- **Radio role for the preset row** - rejected: breaks existing `button` name lookups; `aria-pressed` conveys the state.
- **Render the dialog inside the strip or the log** - rejected: a dialog inside a `role="log"` container, and its prompt-alt image would count in `within(log)` assertions (S7).
- **Store `editOfVersion` whenever an attached version exists (no session check)** - rejected: the cross-session seed (U-11) gives a multi-image first generation a false "Edit of v1" that the read-side rule cannot catch.
- **Trigger D-8 by a failing save only** - not sufficient alone: the save port gives X-18, a different alert; the archive-builder port keeps X-21 reachable.
- **A three-function `preset-recording.ts` module** (v1) - dropped: with SQ-2-A the wire and recorded values are two draft fields, and the functions would be one-line accessors.
