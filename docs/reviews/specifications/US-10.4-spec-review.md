## 2. Non-verifiable language

None is blocking; each is inherited from a Story AC or backed by a measurable sibling clause. Carried over from v1 unless
marked new.

- **FR-16** — "and the navigation is fully usable."
  - A test would have to invent: what "usable" means beyond "reachable and operable" (inherited from AC-6a).
- **FR-14** — "the light values are chosen by the developer" / "derived from the same design tokens".
  - A test would have to invent: what "derived" means. The checkable parts are "no shell surface keeps a dark-theme colour" and FR-15's 4.5:1.
- **FR-15** — "Text is high-contrast (for example white or light grey in the dark theme)."
  - A test would have to invent: a threshold. The 4.5:1 sentence is the measurable form.
- **FR-9** — "In panel-less modes the main area uses the width the panel no longer takes."
  - A test would have to invent: a measurable width. Not checkable in jsdom; falls under FR-16 / FR-19.
- **FR-11** — "its position is not a fixed pixel offset unrelated to the header."
  - A test would have to invent: how "unrelated" is judged. The sentence before it (top edge equals header bottom edge) is the checkable form.
- **FR-9 (new in v2)** — "The panel has a header strip with a height that does not depend on the mode."
  - A tester would have to invent: how to measure it, and the manual matrix of FR-19 lists no cell for it (it names the FR-11 overlay geometry, not the strip height across modes). jsdom cannot check it either. See finding 4.
- **FR-9 failure path (new in v2)** — "any text other than what FR-11 specifies for the History button".
  - A tester would have to invent: what text FR-11 specifies. FR-11 specifies no label or name for the History button (today it carries only `title="History"`). The reference is dangling. See finding 3.

## Non-blocking findings

1. **Edits beyond the three amendments (disclosure).** The revision note says "The three changes" and "Every other proposed
   choice of v1 is ratified as written", but v2 also contains edits that no amendment asked for, apparently adopting my v1
   non-blocking findings 1, 4 and 5: (a) FR-2 base text now qualified by "except the active mode's item as in (a)"; (b) FR-11
   now states that returning to generator shows the overlay again; (c) FR-13 / OD-27 block now lists the rail's own edge and
   the group separators as shell borders (v1's block named the panel's outer border only). (a) and (b) restate behaviour
   already ratified or unchanged from today. (c) widens what the manual evidence (AC-9) must cover, and it sits under a
   heading that says "human ratification" although the approver ratified the narrower v1 text; the widening agrees with
   Story AC-5 ("borders `#26324a`"). I judge all three benign and not a reason to loop back, but the human should be told, and
   the revision note should say so (at the next Specification revision, if any; otherwise the approver can accept (c) knowingly).
2. **Ratification wording vs the recorded gate.** The Specification says the owner "ratified them via /so:approve" and that
   the settled items come from "human ratification at HUMAN_SPEC_APPROVAL". The history records that visit as
   `HUMAN_REJECTED`: an approval with amendments, routed back so the text could be amended first, with no artifact marked
   `APPROVED`. The decisions are the owner's, but v2 as a whole is not yet approved. Also, the Open Decisions log (v3) still
   marks OD-22, OD-26 and the FR-5 key as OPEN, so a later stage reading only the log would see them undecided. Suggest the
   orchestrator or clarifier record the three answers in the log before or at the next approval, and that nothing downstream
   treats "ratified" as a completed gate.
3. **FR-9 dangling reference.** The header failure path forbids "any text other than what FR-11 specifies for the History
   button", but FR-11 specifies no text for it. Say what the History button's visible text or accessible name is (or that it
   is unchanged), so a test can pin "the header contains nothing else".
4. **FR-9 header height is not covered by the manual matrix.** "A height that does not depend on the mode" has no cell in
   the FR-19 proposed minimum (which covers colour, contrast, fit and the FR-11 overlay geometry). OD-28 at TEST_WRITING should add one or drop the sentence.
5. **FR-16 / OD-29 feasibility.** Unchanged from v1: with the expanded rail (256 px) and the panel (384 px) the main area at
   1024 px is about 384 px under `overflow-hidden`; FR-16 may need a Story amendment. ARCHITECTURE_PLANNING must measure first.
6. **FR-19 evidence author and stage** remain deferred to OD-28 (TEST_WRITING), as in v1.
7. **Language control in the icon-only rail.** FR-6 requires the accessible name to contain the visible "EN" / "UA". In the 64 px
   rail the code must therefore stay visible on the control (it is the only visible label). The Specification does not say so
   explicitly; TEST_WRITING and the manual matrix should check it in the collapsed rail.
