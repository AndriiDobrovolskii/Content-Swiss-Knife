### NB-1 (malformed stored base64 throws in the render path): CLOSED

Change: in `StudioMediaService.sizeOf` the `getBytes()` call moved inside the `try` of the async IIFE (`studio-media.service.ts` around lines 38 to 53). A throw gives `null` size; the `Map` entry is already set, so the key is cached and never retried.

Probe results (`sizeOf(key, () => fromBase64(data))`, as `StudioImageTileComponent.label` calls it):

| Stored `data` | Synchronous throw out of `sizeOf` | Signal value | Second call with a getter that throws "should not be called again" |
|---|---|---|---|
| `'!!!'` | no | `null` | same cached signal returned, getter not invoked |
| `'@@@@'` | no | `null` | same |
| `{a:1}` (object) | no | `null` | same |
| `''` | no | `null` | same |
| `12` (number, decodes) | no | `{2,3}` (stub codec) | same |
| valid PNG base64 | no | `{2,3}` | same |
| getter that throws `Error('boom')` | no | `null` | getter calls over 3 invocations of `sizeOf` = 1 (never retried) |

Every other site that decodes or builds a URL from stored data (grep for `fromBase64|atob|toBase64|btoa|inlineData|mimeType` over non-spec `src`):

| Site | Behaviour on malformed base64 |
|---|---|
| `StudioImageTileComponent.label` (the only render-path `fromBase64`, `studio-image-tile.component.ts:53`) | Covered by the guarded `sizeOf`. Label degrades to `vN`. |
| Version strip, full view, tile `srcOf` | String concatenation `data:${mime};base64,${data}` only; no decode. The browser fails to render the `<img>`; no throw. |
| `StudioMediaService.thumbFor` (turn card) | `toBase64(stored.bytes)` is `btoa` over bytes the app itself stored, inside a `try`; the inline branch is string concatenation. No decode of stored text. |
| `StudioDeliveryService.sourceOf` (`fromBase64`, used by download, copy, download all) | Runs inside `run()`'s `try/catch`. Probe with `data = '!!!'`: `download` saved 0 files, message `X-18`; `copy` wrote 0 to the clipboard, `X-18`; `downloadAll` saved 0, `X-18`. |
| Composer, `generation-runner`, `image-ingest` `toBase64` (`btoa`) | Encode bytes the user just uploaded; not stored data. |
| `ImageStudioStore.versionImage` (Edit seed) | Copies `mimeType`/`data` strings; no decode. |

Result: no remaining unguarded decode of stored data in the render path.

### NB-2 (`inputRefs` unbounded at read time): CLOSED

Change: `MAX_INPUT_REFS = 10` and `if (refs.length >= MAX_INPUT_REFS) break;` at the top of the loop in `readTurnExtras`, before the validity check, so only entries that pushed count (`schemas.ts`).

Probe results (`readTurnExtras({inputRefs})`):

| Input | Result |
|---|---|
| 5,000 valid entries | 10 kept, in stored order (`t0`..`t9`), 0.12 ms |
| 5,000 entries, all invalid (`null`, `{turnId: 5, partIndex: 1}`) | `inputRefs: []` (key present, empty) |
| 30 valid among 180 invalid (null, string, partIndex -1, 1.5, NaN, '1') interleaved | 10 kept, `t0`..`t9` (invalid entries do not consume the cap) |
| 4,000 `null` then 12 valid | 10 kept |
| exactly 10 valid | 10 |
| 9 valid, `null`, 1 valid | 10 (the null is skipped, the tenth valid is kept) |
| array-like object `{length: 1e9, 0: ...}` | not an array: no `inputRefs` key |
| sparse array of length 1e7 with one entry | 1 kept, 158 ms (the `for...of` visits holes; bounded by the array length, which a structured-clone IndexedDB record cannot make larger than its stored size in practice; see O-4) |
| entry with a getter that throws | throws out of `readTurnExtras` (O-4: not reachable from IndexedDB data; structured clone evaluates getters at write time and stores plain values) |

The cap of 10 exceeds the real maximum of 6 (5 uploads plus the attached version), so no legitimate record is truncated; the specs `schemas.spec.ts` "exactly the cap", "fewer than the cap", "5,000 references", "bad entries interleaved among 12 good ones" pass (`npx vitest run src/utils/image-studio/schemas.spec.ts feed.spec.ts test/image-studio-theme.spec.ts` -> 3 files, 151 tests passed).

The `images` list on the turn card is per version of that turn, derived from the 20-session-capped, `isImagePartOf`-filtered data, as in v1; v1 NB-2's concrete amplification was the thumbnail list, and that is now at most 10 entries per turn.

### NB-3 (stored `inlineData.mimeType` cast, not validated): CLOSED

Change: `isImageMime(value: unknown)` = `ImageMimeSchema.safeParse(value).success` (a `z.enum` of the three image MIMEs). Applied in `StudioDeliveryService.items` (`mime = isImageMime(inline?.mimeType) ? inline.mimeType : null`), in `StudioMediaService.thumbFor` inline branch, and in the `fileData` branch (`sentMime = stored ? stored.mimeType || mimeType : null`, then `isImageMime(sentMime)`).

Probe, `isImageMime` alone: true for `image/png`, `image/jpeg`, `image/webp`; false for `text/html`, `image/svg+xml`, `application/octet-stream`, `image/gif`, `image/png; charset=utf-8`, `image/png;base64`, `''`, `' image/png'`, `'IMAGE/PNG'`, `'image/png\n'`, `5`, `null`, `undefined`, `{}`, `['image/png']`, an object whose `toString()` returns `image/png`, and the prototype keys `'constructor'`, `'__proto__'`, `'toString'`, `'hasOwnProperty'`, `'valueOf'`.

### Observations (not blocking)

- **O-1 (pre-existing):** `server/index.js` mounts `cors()` with no origin restriction; unchanged, acceptable for a localhost dev proxy; this change does not affect deployment, binding or origin handling.
- **O-2 (pre-existing, US-10.1 design):** Downloaded bytes are not sniffed against their stored MIME; the result is an inert file with an image extension saved through `Blob` + `saveAs`.
- **O-3:** The untracked `.tmp.driveupload/` directory is in the working tree, not in any commit, and was not inspected or published by this review.
- **O-4 (new, minor, not introduced by a defect in the fix):** `readTurnExtras` iterates `turn.inputRefs` with `for...of`, so a sparse array of length 1e7 costs about 158 ms, and an object with a throwing getter would throw. Both require an in-memory object that IndexedDB structured clone cannot produce (it stores plain values and a dense array of its real length). Requires write access to the app's own origin storage plus a pathological length; the cap bounds DOM work, not the loop. No action needed.
- **O-5 (pre-existing, carried through the Story):** the Edit seed `ImageStudioStore.versionImage` forwards the stored `mimeType`/`data` of an `inlineData` part as `attachedVersion` to the server without `isImageMime`; the server schema only requires a non-empty string, and the composer previews it through `[src]` (Angular URL sanitizer). This mirrors `cedbe8e` (`attachedVersion` existed at the base, `store.ts` line 341 there). The source is the app's own previously stored model output; it reaches an LLM provider payload, not a secret or the sanitizer bypass. Recorded for a future hardening story; not changed by US-10.5 and not blocking.
