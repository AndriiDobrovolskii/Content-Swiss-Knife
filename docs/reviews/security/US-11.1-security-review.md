## Surface 5 - Proxy, error surface, telemetry

### Directed point 1 - `console.warn` in `resolveSlot` (log injection): CLEAR

`server/providers/model-support.js` logs `requestedId` only inside the branch where `RETIRED_GEMINI_REMAP.has(requestedId)` is true. That Map holds two
keys (`gemini-3.7-flash`, `gemini-3.6-flash`), so the interpolated value is always one of two fixed constants, never an arbitrary client string.
A client-supplied id of any other shape (newline-bearing, megabyte-long, `constructor`, `__proto__`) takes the not-remapped path and is never logged
by this line. No sanitisation or truncation is needed, and none is relied on. Residual: one warn line per request that carries a retired id (see N-3).

### Directed point 2 - retired-id Maps and prototype pollution: CLEAR

- Server: `RETIRED_GEMINI_REMAP` is a `Map`, guarded by `provider === 'gemini' && typeof requestedId === 'string'`. `Map.has('constructor' | '__proto__' | 'toString')`
  is false. The fallthrough `findModel` is `Array.find` over the catalog (no object-key lookup), so these keys fall back by tier.
- Browser: `RETIRED_MODELS` is a `ReadonlyMap`; `.get(slot.model)` on a non-string or `__proto__` value returns `undefined`. The migration builds
  `{ ...slot, model: target.model }`; object spread defines own data properties, so an own `__proto__` key in parsed localStorage JSON does not
  change a prototype. `target.model` and `target.provider` come from the constant, not from storage. The provider gate uses `findProvider(...)?.id`, which
  resolves to a catalog id or the slot default.
- Pre-existing (not introduced here): `server/usage/pricing.js` `getPrices` does `DEFAULT_PRICES[model]` on a plain object. `model` there is the resolved
  catalog id (`usage.model` comes from the provider's resolved slot, not the request body), so a `constructor` key cannot reach it from the browser. Observation O-1.

### Directed point 3 - `@google/genai` 1.52.0 -> 2.32.0: CLEAR (non-blocking notes N-1, N-2)

- Lockfile delta (`git diff origin/main..HEAD -- package-lock.json`): 4 lines changed - the root `dependencies` range and the one
  `node_modules/@google/genai` entry (`version`, `resolved`, `integrity`). No package added or removed; no other `integrity` line moved.
- The registry entry `https://registry.npmjs.org/@google/genai/-/genai-2.32.0.tgz` carries an `integrity` sha512 hash. The SDK's declared dependencies
  (`google-auth-library ^10.3.0`, `p-retry ^4.6.2`, `protobufjs ^7.5.4`, `ws ^8.18.0`) and its optional peer `@modelcontextprotocol/sdk` are identical to the
  1.52.0 entry's in origin/main's lock, and already resolved there; so there are no new transitive packages.
- Install scripts: `hasInstallScript: true` was already present on 1.52.0 (unchanged context line). The installed package's `preinstall` is
  `echo 'preinstall: no-op'`; the `prepare`/`build` scripts in its package.json are publisher dev scripts that npm does not run on a registry install. The planner ran
  the install with `--ignore-scripts`; the repo-level install ran lifecycle scripts (N-1). Given the `echo` no-op this is a note, not a finding against the code.
- Per-request undici dispatcher (installed `dist/node/index.mjs` around lines 13619-13650 and 13958-13962): on Node, when no custom `fetch` is given, the SDK
  sets a per-request `dispatcher` object that delegates `dispatch()` to the global dispatcher (`Symbol.for('undici.globalDispatcher.1')`) with `headersTimeout: 0`
  and `bodyTimeout: 0`. It does not call `setGlobalDispatcher`, so it does not replace or alter the process-wide dispatcher that cheerio/retrieval and the
  Anthropic/Serper calls use (grep of `server/` finds no `setGlobalDispatcher`/`ProxyAgent`). It only affects the SDK's own requests. See N-2 for the
  timeout consequence.
- `test/genai-dependency.spec.ts` pins the `^2.32.0` range, the lock entry and the installed 2.x copy (no 3.x).

### Directed point 4 - CONTINUATION error message: CLEAR

The new throw in `gemini.js` is
`[gemini] ${what} truncated: hit finishReason CONTINUATION on ${model}. The response is an unfinished answer that this provider does not continue; the partial text is discarded.`
It interpolates `what` (a fixed call label) and `model` (a catalog id resolved by the server, not request text). The partial
text is not read before the throw and is not in the message. No `status`, no stack, no upstream URL. It reaches the browser through `sendError` ->
`describeError(error)` (message plus a depth-bounded cause chain), the same funnel as the existing MAX_TOKENS error, and appears in the server log through the existing
`formatCallError` detail, carrying the same fixed text.

### Directed point 5 - no key path to the browser bundle: CLEAR

See Surface 1. The shared `model-catalog.json` gained two Gemini model entries and lost two; no endpoint, header or credential field.

### Directed point 6 - usage database rows: CLEAR

`server/usage/store.js` is not in the diff and `insertUsage` takes the same fields as before (provider, model, mode, taskLabel, productName, store, lang, token
counts, costUsd). `pricing.js` adds only price-table entries and a pure date helper (`gemini4CarbonPrice(now)`) - no new column, no new field written, no
prompt/response content. `usage.model` remains the resolved catalog id. `call-log.js` is not in the diff (the `test/call-log.spec.ts` change swaps fixture model ids only); no
full-payload logging was added.

### CORS / binding

unchanged; this Story does not affect deployment, binding or origin handling. `arch-guard.sh` exits 0 on HEAD.

## Findings

| N-1 | Non-blocking | yes (dependency bump) | Install-script surface of the new SDK version was inspected statically (`preinstall` is an `echo` no-op, `hasInstallScript` was already true on 1.52.0). No code change needed; an `npm audit signatures` / provenance check could be added by the owner. |
| N-2 | Non-blocking | yes (SDK upgrade) | 2.32.0 sets `headersTimeout: 0` / `bodyTimeout: 0` on the SDK's own undici requests, so undici no longer bounds a stalled Gemini connection; only the SDK's abort timer (`httpOptions.timeout`) does. Verified in source: every `generateContent` / upload call in `gemini.js` passes an explicit timeout (`timeoutForMode(mode)`, `UPSTREAM_TIMEOUT_MS`, `VISION_TIMEOUT_MS`, `FAST_TIMEOUT_MS`) and the constructor sets `DEEP_TIMEOUT_MS` as the floor, so the accepted rationale (bounded requests) still holds. It widens an existing resource-exhaustion surface that rests on those timeouts staying in place; that the SDK's abort timer fires on a stalled body is not proven here (U-1). |
| N-3 | Non-blocking | yes | `resolveSlot` emits one `console.warn` per request carrying a retired id, with no rate limit. The text is a fixed constant pair, so there is no injection; a stale client only produces log volume. Accepted for a localhost dev proxy. |
| O-1 | Observation | no (pre-existing) | `getPrices` looks up `DEFAULT_PRICES[model]` on a plain object. Safe today because `model` is a resolved catalog id, not request input. Do not block this Story. |
| O-2 | Observation | no | Gemini 4 Carbon becomes the first-premium fallback in `resolveSlot`/`defaultModel` (documented in the code comments and spec N-4). This changes which model an unknown Deep id is routed to (a cost/behaviour change), not a secret or injection surface. |
| O-3 | Observation | no | CORS remains an exact-match allow-list defaulting to `http://localhost:3000`; unchanged and fine for a local proxy. |
