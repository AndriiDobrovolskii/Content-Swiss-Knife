## 6. What this change specifically touches

### 6.1 `localStorage` key `seo_gen_shell_rail_expanded`

| Aspect | Evidence | Result |
|---|---|---|
| What is stored | `String(expanded)`: the literal `'true'` or `'false'`. No user input, no identifier, no secret, no timestamp. | Safe |
| Read parsing of an untrusted value | `getItem(KEY) !== 'false'`: only the exact string `'false'` yields collapsed; every other value (absent, `'null'`, JSON, script text, oversize string) yields expanded. The raw value is never parsed, never interpolated into a template, never reaches `[class]`/`[attr]` (the signal is a `boolean`). **No `JSON.parse`.** This is stricter than the neighbouring pre-existing read of `seo_gen_dark_mode` (`JSON.parse(savedDark)`, O-1). | Safe |
| Blocked storage | `readRailExpanded` wraps both the `() => localStorage` accessor (which throws `SecurityError` when site data is blocked) and `getItem` in `try/catch` and returns `true`; `writeRailExpanded` swallows a throwing `setItem` (blocked or quota). The click handler therefore cannot throw and the in-memory signal still flips. | Safe |
| Write timing | Written only in `toggleRail()` (no `effect`), so nothing is written on load. | Safe |
| Exposure | Same-origin only; another origin cannot read it. A same-origin script able to alter it can only toggle a layout width. | No impact |

### Observations (pre-existing, untouched by this change; not blocking)
- **O-1.** `app.component.ts` still reads `seo_gen_form_state` and `seo_gen_dark_mode` through an unguarded `localStorage.getItem` and `JSON.parse` (lines ~718 and ~735); blocked storage or a corrupted value crashes the constructor.
