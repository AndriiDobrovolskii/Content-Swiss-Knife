## Findings

All non-blocking; none sends the Story back.

- **R1 (for the human).** Story AC-14 and FR-29 say "no surface keeps dark colours in light mode"; the plan's DD-15 (ratified at plan approval, not a Story or spec text) exempts two class strings: `text-red-700 dark:text-red-300` and the fixed `bg-slate-900/70 text-white` scrim over images (thumbnail remove buttons, upload caption, version badge, compare labels). The scrim is a small dark label over an image, not a theme surface, and C-4 measured it at >= 6.67:1 in both themes; I judge it compatible with the intent, but the literal AC wording does not mention it. Not a gap; the human can confirm at the gate.
- **R2 (for the human).** The Story's AC-15 is a closed list; the spec's OD-20 remainder widens it to text changes (e.g. `PRN-1..3`, "Edit this →" rows in `studio-texts.spec.ts`). These are consequences of Story-named changes and were accepted by the bare spec approval; each one is listed in the implementation report. No action beyond awareness.
- **R3 (carried N1).** `apply-response.ts:144` says display fields are "written only when defined", but `modelTurn.cost = response.costUsd` (line 145) is unconditional. `costUsd` is typed `number`, so no `undefined` is stored and AC-13a ("writer omits keys") holds for every optional key that can be absent. The comment is broader than the code. Cosmetic.
- **R4 (carried N2).** The compare-slider handle glyph `&#8596;` (`studio-compare-slider.component.html:30`) is `aria-hidden`, language-neutral and carries no meaning (the slider name is `X-42`). It is outside the plan's two listed literals (`Ctrl ↵`, `v{N} · {W}×{H}`) but NFR-5 is about labels, accessible names and hints, which it is not. Accepted; list it in the PR notes.
- **R5 (carried N3).** `.tmp.driveupload/` is untracked and not part of this Story; it must not be staged at PR preparation.
- **R6.** The T34 composer case titled "FR-16: the aspect ratio stays the native select with the six values, 4K needs Pro, ..." asserts only the select tag, the product field and Cancel. AC-10 is nevertheless covered by the older "AC-9 / FR-19" cases (exact six options, 4K only for Pro) and by the absence case, so this is a naming overclaim, not a gap.
- **R7.** Several matrix titles are paraphrases of the real ones (for example matrix "FR-23 / NFR-1: history is the {id, role, parts} projection (T4)" is "US-10.5 FR-23 / NFR-1: history is the ... of the stored turns (T4)"; matrix "FR-6 / D-5: the download-format selector is gone (T21)" is "... is gone from the studio (T21)"; the AC-16 row names a describe "US-10.5 FR-33 / FR-20 (T33)" that is an `it` inside "US-10.5 FR-13 / FR-3 (h) / FR-11 (T33)"). Each test exists and is findable; the matrix was written before implementation and v1 was never refreshed. Matrix edits are out of this stage's scope.
- **R8 (carried N4, N5).** quality_gate_report v2 and implementation_report v2 name `2dbd9e4` (the first Story commit) as the base; the true pre-Story base is `cedbe8e`. The approved plan v2 text for DD-15 still lists the amber scrim as exempt; PR text must cite the amended DD-15 (two entries). `src/app/app.component.html:955` outside the studio still has `bg-amber-600`; out of scope.

Leave for a hardening story.
