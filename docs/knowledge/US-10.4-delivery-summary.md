# US-10.4 delivery summary — the app shell: grouped, collapsible navigation and restyled layout in light and dark themes

## What was delivered
The global header controls and the in-panel mode switcher were replaced by a left navigation **rail** and a **mode-gated input panel**, restyled with
one set of shell colour tokens in a light and a dark theme. Part 1 of 3 of the Image Studio redesign (US-10.5 and US-10.6 follow and are not part of this
delivery). Angular shell only: six product files changed, no `server/`, prompt, renderer, validator or `STORE_REGISTRY` file, no FROZEN file.

- **Rail** (`<nav>`, 256 px expanded / 64 px icon-only): three groups with a derived count (SEO and Text 9, Images 2, Code 1; English and Ukrainian
  names), each collapsible and open by default, one `aria-current="page"` item, a collapse/expand control, and four bottom controls in the order
  Dashboard, Language, Theme, AI Settings. Expanded or icon-only is persisted under `localStorage` key `seo_gen_shell_rail_expanded` (`true` means
  expanded; guarded read and write, nothing stored on load). The Language control's accessible name starts with its visible code (`EN, …` / `UA, …`).
- **Panel** (`<aside>`): rendered only in the ten panel modes; absent from the DOM in HTML Editor, Dashboard and Image Studio. Fixed 64 px header strip
  with no mode label, holding only the generator-only History button; the History overlay anchors to the strip through one shared `--shell-header-h`
  value. Clear All, the improvement-request block and the other panel controls are gated with the panel.
- **Colours**: eight `--shell-*` tokens (light on `:root`, dark on `html.dark`) exposed as a Tailwind `shell` colour family; opaque `<main>` so the
  page background `#0b1120` is actually visible; rail and panel chrome `#111a2e`, borders `#26324a`, accent `#7c3aed` only for the active icon, the
  active left border and focus rings. Mode interiors keep their `slate-*` colours.
- New pure module `src/app/shell-nav.ts` (navigation table, group counts, shown-item and panel rules); six new copy keys in English and Ukrainian.

## Claim limits (what this delivery does not say)
1. **FR-16 is "met under the product owner's reading of U-1".** The approved Specification's parenthetical, "no horizontal scrolling is required to reach
   anything", is not met literally: in-component horizontal scrollers exist in 10 of 13 modes, all already present at 640 px. Clipped content is 0 in
   every measured cell. The Story and Specification were not amended.
2. **Not "mode interiors untouched".** The owner-permitted `seo-generator` tooltip CSS fix (`6ac207a`: `opacity-0 invisible` to `hidden
   group-hover/tooltip:block`, the fade dropped) is a mode-interior change outside `task_breakdown` v2.
3. **T9 edited `src/app/app.component.ts`** (the colour strings of `navItemClass()` and `navIconClass()`, and an optional mode argument) although the
   T9 file table does not list it; the plan places that logic there.
4. **The manual evidence was gathered by an agent** (Claude in the owner's Chrome 156), not an independent human. AC-5 is partial, AC-6, AC-6a and
   AC-9 are manual or structural; hover and light-theme focus contrast were not fully tabulated; the final-build FR-16 re-measure is prose with
   per-mode counts, no raw table (the raw phase-2 tables are on `6ac207a`).
5. `test/shell-evidence.spec.ts` accepts any text after `FR-16 met:`, so AC-9's automated check cannot protect the FR-16 verdict.
6. Tests (`4acd8ab`) and documents are separate commits from the T3 to T9 code commits, not inside them (a deviation from the tests-with-code expectation
   of `AGENTS.md` section 13); the two adapted specs are partly red against the intermediate T4 and T6 commits by design, and the per-commit buildability
   of T4 to T6 was not re-checked. History was not rewritten.
7. The coverage numbers do not include `src/app/shell-nav.ts` (outside the vitest coverage include, pre-existing config); it is covered by its 110 cases.
