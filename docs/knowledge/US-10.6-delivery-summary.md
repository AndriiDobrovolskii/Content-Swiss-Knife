# US-10.6 delivery summary — Image Studio new capabilities: Upscale 4K, Variation, several images per generation, Style ref, saved presets, spend totals, pre-send estimate

## What was delivered
Part 3 of 3 of the Image Studio redesign (US-10.4 shell and US-10.5 visual layer are merged). Angular track with server work: `server/image-studio/**` and
`server/usage/pricing.js` changed; no `server/providers`, `src/domain`, `src/prompts`, `src/render`, config, `.env.example`, `package*.json` or FROZEN file changed.

- **Several images per generation.** An "Images" select (1 / 2 / 4, default 1) sits before the ratio, resolution and model selects. One generate request carries
  `imageCount`; the BFF grants `min(units, N)` from the hourly limiter in one atomic step, makes that many parallel upstream calls and returns ONE merged `images`
  response in slot order plus a `batch` report (requested / granted / succeeded, a closed failure cause per failed call). One model turn per response keeps the
  history alternating. Each successful call writes its own usage row priced at its own image count. Cancel discards the whole action (owner ruling G-2 A).
- **Pair-priced cost and the estimate.** `imagePrices` lives in the shared contract JSON, keyed by model and resolution; `getImagePrice` / `computeImageCost`
  take the resolution as a required argument and throw for an unknown pair. An unpriced pair answers `PRICE_NOT_CONFIGURED` (500) before any upstream call. The
  composer shows "≈ $X for N images" left of Generate (two decimals, display only; the client estimate equals the server cost, input charges excluded).
- **Upscale 4K and Variation.** Both buttons sit on every generated image (Download, Upscale 4K, Variation, Edit this). Both send the chosen version inline with an
  empty history and no instruction text; Upscale asks for 4K on the Pro model (a Flash session still offers it and runs on Pro), Variation repeats the source
  version's prompt, resolution and ratio for K results. The new version stores the source version's prompt.
- **Style ref.** Each uploaded thumbnail has a Product / Style ref toggle; one Style ref per generation, outside the five-upload limit, a second one is refused. The
  sentence from the Story is sent once, as its own text part right AFTER the Style ref image, from a non-frozen `src/prompt-core/image-studio-instructions.ts`. The
  role tag is stored at Turn level (`styleRefPartIndex`) and is never sent to Gemini; a reloaded card shows the "Style ref" label. A send whose only content is a Style
  ref image is refused.
- **Saved presets.** "+ Save current as preset" (dashed pill after the registry group) saves prompt, ratio, resolution and model under the typed name (name cap 60,
  count cap 30, `user-` ids that can never equal a registry id), in the browser's localStorage behind a port. A preset applies like a registry preset except the
  prompt is literal; a stale model or resolution falls back to the default; each user preset has a delete button (named "Delete preset ...", revealed on hover and
  focus by CSS).
- **Spend totals.** "Today $X · month $Y" at the right end of the header from the existing `GET /api/usage` (UTC day and month, `image-studio|` rows with a null mode),
  fetched once on open and after an action that added images; a neutral placeholder (an aria-hidden dash) while loading or after a failure, never `$0.00`.
- **Feedback.** Rate-limit and partial-failure messages ("Rate limit reached. Generated 2 of 4 images.", "Could not generate k of N images.", one line per cause) are
  fed to the ONE `role="alert"`; exactly one `role="status"` per finished action; focus returns to the prompt field after every ending of Generate, Upscale or Variation.
- All new texts exist in en and uk (`X-45..X-62`), copy taken verbatim from the owner's ruling.
