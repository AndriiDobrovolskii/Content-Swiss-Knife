# US-11.1 delivery summary — Gemini 4 Carbon and Gemini 4 Hydrogen replace Gemini 3.6 Flash and 3.7 Flash in the model settings

## What was delivered
The Gemini provider's text-model list in the AI Model Settings changed from Gemini 3.1 Pro, 3.8 Flash, 3.7 Flash, 3.6 Flash to **Gemini 4 Carbon, Gemini 3.1 Pro, Gemini 4 Hydrogen,
Gemini 3.8 Flash** (in that order; the two image models are untouched and stay out of the text slots). Track angular, with server files. No prompt, renderer, validator, schema,
`src/domain`, `src/utils` or FROZEN file changed.

- **Catalog.** `src/prompt-core/model-catalog.json` drops `gemini-3.7-flash` and `gemini-3.6-flash` and adds `gemini-4-carbon` (tier `premium`, levels low/medium/high, default
  medium, 65536 ceiling) first and `gemini-4-hydrogen` (new tier `balanced`, low/medium/high, default high, 65536) third. `model-catalog.ts` widens both tier unions to
  `premium | balanced | fast`. `minimal` is no longer offered by any text model. The shared reorder moves the Gemini default model, the premium tier fallback and the Deep provider
  switch from 3.1 Pro to Carbon (N-4, documented in `resolveSlot` and `defaultModel`).
- **Third cost badge.** The settings panel shows `$$$` for Carbon and 3.1 Pro, `$$ ⚡` for Hydrogen (own sky colour set with light and dark variants, exhaustive
  `Record<ModelSpec['tier'], string>` lookups) and `$ ⚡` for 3.8 Flash.
- **Dropdown default level (OD-4 reading 2).** Selecting Carbon or Hydrogen in either slot's dropdown sets its default level (medium / high); every other model keeps the
  carry-over with clamp. A provider switch lands on Carbon (Deep, medium) or 3.8 Flash (Fast).
- **Migration of stored choices.** The browser restore maps a stored `gemini-3.7-flash` / `gemini-3.6-flash` to `gemini-3.8-flash` when the slot's effective provider is
  gemini (a `Map`, so ids such as `constructor` / `__proto__` no longer count as retired — a latent bug fixed), clamps `minimal` to `low`, persists once and does not migrate
  again. The server `resolveSlot` remaps the same two ids with one `console.warn` per call. A retired-id slot with no stored level resolves to `high` (P-9b = A, no new code).
  The two tables exist twice (browser and server) by design, because the catalog JSON may not contain a retired id.
- **Pricing.** `server/usage/pricing.js`: Hydrogen flat 1.50 / 7.50 / 0 / 0.075; Carbon by the instant of each lookup, 2.00 / 10.00 / 0 / 0.10 before 2026-12-01T00:00:00Z and
  4.00 / 20.00 / 0 / 0.20 from that instant; the retired entries and their helper removed; 3.1 Pro and 3.8 Flash prices unchanged.
- **SDK.** `@google/genai` raised from `^1.43.0` (1.52.0) to `^2.32.0` (2.32.0); lock delta limited to the root range and the package entry (8 diff lines, no transitive
  movement). The comments in `server/providers/gemini.js` about the SDK internals were refreshed to what 2.32.0 does; no code change there other than the guard below.
- **CONTINUATION guard.** `GeminiProvider#readText` throws on `finishReason === 'CONTINUATION'` (a new FinishReason in the 2.x SDK) with an error that names the model, carries none
  of the partial text, has no `status` and no transient marker, so it is a single attempt and the Doc repair gate stops at once. `generate`, `analyzeImage` and
  `extractFromPdf` all read through that one function.
- **Docs.** `.env.example` comment text describes the new catalog (no `KEY=` line changed). A closed-list scan (`test/active-docs-models.spec.ts`) keeps `README.md`,
  `.env.example`, `AGENTS.md` and the active source files free of the retired names, allowing them only in the two recognition tables and their migration comments.
  `AGENTS.md` was NOT edited (NB-11).
