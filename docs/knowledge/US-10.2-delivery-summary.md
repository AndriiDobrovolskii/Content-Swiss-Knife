# US-10.2 delivery summary — Node runtime pin and the cheerio `undici` pin, together and verified live

## What was delivered
The Node runtime and the `undici` copy that `cheerio` loads are now pinned as one pair, and a guard test enforces that they agree.
Dependency and tooling change only: no `src/` or `server/` code changed.

- `.nvmrc` = `24.22.2`; `package.json` `engines.node` = `24.22.2` (an exact string, OD-2); `overrides.cheerio.undici` `7.24.4` → `7.30.1`
  (the `undici` bundled in Node 24.22.2). The `package-lock.json` nested entry `node_modules/cheerio/node_modules/undici` was
  re-resolved by `npm install` (no hand edit); `npm install` run twice gives an identical lockfile.
- `test/undici-pin.spec.ts` (42 cases, written by TEST_WRITING, red 7 / green 42 on the unchanged-then-changed tree) fails when
  `.nvmrc`, `engines.node` and the pin disagree, when the running Node is not the pinned one, or when the pin differs from
  `process.versions.undici`. It compares a relationship, not a version window, and it fails (never skips) on another Node.
  It is advisory outside the tests: no `engine-strict`.
- README Prerequisites names the pinned Node (`24.22.2`, pinned in `.nvmrc`).
- Live evidence (`docs/evidence/US-10.2-node-undici-pin-live-evidence.md`, a registered `evidence` artifact): the real
  `POST /api/image-studio/upload` returns HTTP 200 with a `fileUri` on the pinned Node (object deleted); the same upload without the
  override (scratch tree, hoisted `undici` 7.28.0, after one permitted `npm dedupe`) also returned 200, recorded as data only; a ten-run
  `test:logic` series on Node 24.22.2 showed no worker-exit marker.
