# US-10.1 delivery summary — Image Studio (Nano Banana) for multi-turn product image generation and editing

## What was delivered
A new **Image Studio** mode in the app: an operator uploads up to five product images, writes a prompt (or picks a preset and
chips), and edits/generates visuals in a multi-turn chat with Gemini image models ("Nano Banana"). The mode is isolated from
the description generator and is its own lazy-loaded chunk (`image-studio-component`, 74.64 kB raw).

- **Server (BFF).** New routes `POST /api/image-studio/upload` and `/generate` under `server/image-studio/*`, mounted by
  `createApp` in `server/app.js` after CORS and a pre-parser `Content-Length` body limit (30 MiB, 413/411). Per-IP fixed-window
  rate limiter (30 counted requests per window, `Retry-After`, CORS headers on 429), fixed 1000/2000/4000 ms retry loop,
  request schemas, server-side magic-byte detection of uploads, size and token trim of the history (pair removal, 80% of the
  input limit, real `countTokens`), response classifier (images / safety / text-only / failed), `FILE_MISSING` recognition (410),
  image pricing and a usage row labelled `image-studio|<preset>|<resolution>`. Gemini calls live only in
  `server/providers/gemini.js` (`generateImage`, `uploadFile`, `countTokens`); no system instruction is sent; no retrieval.
- **Client.** `src/utils/image-studio/*` (ingest with re-encode and EXIF drop, upload rules, alt text, file names, output format
  and delivery conversion, ZIP of versions, request builder, response application with numbering, session lifecycle with expiry
  and cap, error dispatch, generation runner with Cancel, 120 s deadline and the `FILE_MISSING` re-upload round),
  `src/services/image-studio/*` (root signal store, IndexedDB session store, canvas codec, tokens with root defaults),
  `LlmService` image methods, and the components `ImageStudioComponent`, composer (presets, chips, model/ratio/resolution
  selectors, attachments), version strip (full view, download, copy, ZIP), session list. Presets live in
  `src/prompt-core/prompt-presets.ts`; the two Nano Banana models are in the shared model catalogue (text-only views stay
  image-blind). The dashboard gets the studio bucket additively.
- **Dependency change (human-approved, AGENTS.md §7.8, NFR-7 exception).** `package.json` `overrides.cheerio.undici = 7.24.4`
  plus a `package-lock.json` nested entry: with the hoisted `undici` 7.28.0 loaded by `cheerio`, the Gemini Files API upload
  failed in the full server (`UND_ERR_INVALID_ARG`). 7.24.4 equals the `undici` bundled in Node 24.15.0.

## Rework after the first PR approval (what the gates missed)
The first `HUMAN_PR_APPROVAL` was **rejected by the human**: uploading an image in the running app returned 404. Every gate had
been green because all tests fake Gemini. Two real defects were then found with live probes:
1. `files.upload` in `@google/genai` 1.52.0 replaces its resumable-upload start headers whenever `config.httpOptions` is
   present (404) and ignores `config.abortSignal`; fixed in `719c0b3` (provider-side abort/timeout race and orphan cleanup;
   the committed test that pinned the broken contract was corrected by TEST_WRITING).
2. `cheerio` loads the npm `undici`, which rejects the SDK's `Content-Length` on upload chunks (502 in the full server);
   fixed by the scoped override in `14122a8` with a guard test `test/undici-pin.spec.ts` (checks the pin only; the proof was a
   real-route call: HTTP 200 with a `fileUri`, object deleted).
A third issue, a **Node v24.15.0 / Windows fault** (vitest worker exit `0xC0000409` on many short-lived `agent:false` loopback
connections), made `npm test` fail intermittently; it is **mitigated, not fixed**, by a shared keep-alive agent in two
loopback specs (`4723778`).
