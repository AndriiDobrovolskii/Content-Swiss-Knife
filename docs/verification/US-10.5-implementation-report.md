## What the branch implemented

A visual and structural restyle of Image Studio onto the shell tokens with no new generation capability: a header and slim session list, a result-card feed (replacing the chat log) with input thumbnails, chips, summary line, interleaved text and image tiles, Reuse prompt, native one-click download, Edit-of / Compare chips with a keyboard-operable compare slider in a full-view dialog, Download all (.zip with a deterministic name), an empty state with starter preset cards, a restyled composer (chips above the prompt, Generate button with `Ctrl ↵` hint driven by `sendState`, preset check mark), additive optional stored fields (cost, duration, preset, input refs, edit source) kept out of the resend payload and out of the zod objects, and a theme-token scan. Tracks: `angular` for all tasks. `server/` is untouched. The only prompt-core change is `src/prompt-core/prompt-presets.ts` (not FROZEN). No FROZEN file, `vitest.config.ts`, `tsconfig.json`, `angular.json`, `arch-guard.sh` or `.arch-guard-checksums` changed.

## Interpretation notes the plan asked to list

- **R-6 (orphan first user turn).** The card feed shows one card per stored model turn. A first user turn whose model turn was cut is no longer shown, where the old chat log showed it as a bubble. A visible difference in long sessions only; the cut itself is still announced by T-9. Recorded as plan finding F-5; accepted, not a defect.
- **R-11 (native download supersedes US-10.1 D-22).** Download now delivers the MIME the studio holds (`item.mime`, the API bytes) with the extension derived from it, one click, no format selector, no codec call (FR-6, SQ-5-B). US-10.1 D-22 (default conversion to the upload's format) is superseded: a user who relied on their upload's format now gets the held format. Consequences recorded: `delivery.ts`, `zip.ts`, `output-format.ts`, `file-name.ts` are UI-unreferenced after T21 but their specs are untouched (FR-6 Proposed); the transcode-failure tests (old strip L198-207, L298-305) can no longer be reached and are replaced by D-8, not dropped.
- **DD-15 (colour exemption), as AMENDED in test_strategy v8 section 12.** Studio markup uses only the existing eight `--shell-*` tokens through the `shell` Tailwind family and carries no `dark:` variants; `index.html` and `src/styles.css` are not edited. Two classes of colour stay outside the token rule because the `shell` family has no error or overlay colour and FR-29 forbids a new palette value: (1) status text in `role="alert"` regions keeps `text-red-700 dark:text-red-300` (the pair stays whole for 4.5:1 on dark); (2) fixed dark-on-image overlays `bg-slate-900/70 text-white` (thumbnail remove buttons, upload captions, the version-number badge). The amber scrim `bg-amber-600 text-white` is REMOVED from the exemption list: the T42 evidence measured it at 3.19:1 (below FR-30's 4.5:1), the human decided to replace it, and T44 made the Retry label `bg-amber-700 text-white` (5.02:1), which needs no allow-list entry. `test/image-studio-theme.spec.ts` therefore exempts exactly two patterns by exact class string (non-vacuous allow-list), and `\bbg-amber-(?:50|[1-6]00)\b` is now an offender. The only other `bg-amber-600` in `src/` is `src/app/app.component.html:955`, outside the studio and out of scope. Contrast, 1024 px, slider drag and the compare frame cannot regress in `ng test`; they are T42 manual evidence, recorded PASS in evidence v2.
- **Owner rulings applied.** OI-A option a: a blank or whitespace-only latest prompt gives an empty row name and an archive named `{timestamp}-image-studio-versions.zip`; a chip latest uses the chip instruction (T38/T39 not applicable, T40 needs no code). OI-B option 1: Reuse prompt counts as an edit, the check mark clears, the wire `presetId` is kept (T41).
