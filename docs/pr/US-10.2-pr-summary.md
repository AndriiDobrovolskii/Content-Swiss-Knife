Closes US-10.2 - Pin the Node runtime and the undici override together.

## What changed

The repository now names one supported Node: `.nvmrc` and `package.json` `engines.node` are both
`24.22.2`, and `overrides.cheerio.undici` moves from `7.24.4` to `7.30.1`, the `undici` that Node
24.22.2 bundles (measured with `node -p process.versions.undici`, not copied). The lockfile moves
only the nested cheerio `undici` entry and gains the root `engines` entry. The guard test
`test/undici-pin.spec.ts` replaces its hard-coded version window with a relationship check (the Pin
must equal the running Node's bundled `undici`, `.nvmrc` must equal `engines.node`, and a run on any
other Node fails rather than skips). The README Prerequisites line names the pinned Node.

No `src/` or `server/` file changed.

## Why

US-10.1 pinned the cheerio `undici` to `7.24.4` because Node 24.15.0 bundled that copy; the pin was
not tied to a runtime, so a different Node silently reopens the dispatcher/bundled-undici skew and
the Gemini Files API upload answers 502 (`UPSTREAM_RETRIES_EXHAUSTED`). AGENTS.md section 7 item 10
now requires the pin to land together with `engines.node` and `.nvmrc`. Moving to Node 24.22.2 and
`undici` 7.30.1 also removes the exposure US-10.1 had accepted: 7.30.1 matches none of the 23
current `undici` advisories, while the old 7.24.4 matched 22 (security review section 1).
