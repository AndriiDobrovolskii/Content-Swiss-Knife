## What the Specification asks for, in blast-radius terms

A model-settings and server-provider change (track `angular`, with server tasks):

1. **Catalog**: two new Gemini text entries (Carbon `premium`, Hydrogen `balanced`) placed first and
   third; two entries removed; the `tier` union gains `balanced` in two declarations (FR-1..FR-5).
2. **Settings UI**: dropdown contents, a third badge text and a sky colour class set, `minimal` no
   longer offered for the three Gemini models that cannot take it (FR-6..FR-9).
3. **Settings service**: provider-switch and dropdown level rules (OD-4 reading 2), retired-model
   restore migration with a persisted-once rule, defaults unchanged (FR-11..FR-18).
4. **Server**: `resolveSlot` remap of the two retired ids (FR-19); `GeminiProvider` `CONTINUATION`
   guard and a verify-only request shape (FR-20..FR-23; FR-22's 65536 clause is the `generate()` path only,
   `analyzeImage` 8000 and `extractFromPdf` 8192 stay); `@google/genai` 1.x to 2.x major upgrade
   (FR-24, FR-25); pricing (FR-26..FR-29).
5. **Docs and specs**: retired names removed from active docs and sources; a long list of existing
   specs rewritten (FR-30, FR-31).

Cross-cutting consequence of the catalog order: Carbon is now the first Gemini model **and** the first
`premium` one. `defaultModel('gemini')` (browser and server), the `premium` tier fallback in
`resolveSlot` and in the service's `pick`, and `clampLevel`'s fallback for an unknown Gemini model
id all change from Gemini 3.1 Pro to Carbon (from source: `defaultModel()` returns `models[0]` and
`resolveSlot` / `pick` use `models.find(m => m.tier === preferTier)`, in `model-catalog.ts`,
`server/providers/model-support.js` and `model-settings.service.ts`).
This reaches more specs than the Specification's P-8 list names (see "Tests that exercise them").

  `files.upload` replacing resumable-upload headers with `config.httpOptions`; `files.upload` ignoring
  `config.abortSignal`) all live behind fakes. If any no longer holds in 2.32.0, the mocked specs stay
  green while Image Studio uploads 404 or a Gateway Timeout stops being retried. The OD-1/OD-2 ruling
  (verify the installed 2.32.0 before ARCHITECTURE_PLANNING) is the only control left. Also unknown to
  the fakes: whether `thinkingConfig.thinkingLevel` still accepts the lowercase strings the code
  passes.
- **R-2 (specs that keep a retired id still pass).** With the catalog entries gone, a spec that
  passes a retired id through `clampLevel` or `findModel` silently takes the `defaultModel('gemini')`
  fallback (Carbon, levels `low/medium/high`, `defaultLevel` `medium`). Examples (from source):
  `model-catalog.spec.ts` 111-112 (`clampLevel('gemini','gemini-3.6-flash','turbo')` toBe `'medium'`
  passes by coincidence on Carbon's `defaultLevel`); `model-catalog.spec.ts` 335-336 (`'high'` is in
  Carbon's levels); `test/image-studio/model-support.entries.spec.ts` 30-31
  (`ids.indexOf(FLASH) > ids.indexOf('gemini-3.6-flash')` becomes `> -1`, **always true**, so the
  "image entries come after the text entries" assertion becomes vacuous); `test/gemini-provider.spec.ts`
  76-182 (`level: 'low'` fixtures with a retired id run unchanged); `test/call-log.spec.ts` (pure
  formatting). Only the `minimal`-asserting ones fail loudly. FR-31 / OD-8 require these to be
  rewritten; there is no automated guard that a retired id is gone from specs, so the rewrite is a
  review item.
- **R-3 (Carbon is the new `premium` default).** An unknown, missing or stale Gemini Deep model, and
  a Deep provider switch to Gemini, now land on the model whose price **doubles** on 2026-12-01 (and
  that is the only Gemini model needing the continuation guard). Nothing errors; the cost does. N-4
  asks for it to be documented.
- **R-4 (price lookup shape).** `getPrices` for Carbon needs an exact-match helper branch; a Carbon
  entry added only to `DEFAULT_PRICES` would not be date-dependent, and a dated or suffixed Carbon id
  (for example `gemini-4-carbon-<date>`) would skip the exact branch and, if Carbon has no
  `DEFAULT_PRICES` key, reach the substring loop and then `FALLBACK_PRICE` (`in 3.00 / out 15.00`: 1.5x the Carbon intro price, 0.75x the post-cutover price).
  Hydrogen (`in 1.50 / out 7.50`) would be overstated 2x by the fallback. `computeCost` takes no clock argument, so only `getPrices(model, now)` can be driven by the
  injectable clock; a cost-level boundary test needs fake timers.
- **R-5 (cutover timezone).** The cutover is `2026-12-01T00:00:00Z`, so billing shown for up to about
  8 hours before a Pacific-time flip is the higher price (Story Q6; conservative direction). No error.
- **R-6 (Hydrogen `high` by default).** Under OD-4 reading 2, selecting Hydrogen sets level `high`,
  which the settings panel already marks with the "High noticeably increases response time and API
  cost" warning, and `high` is Hydrogen's most expensive level. Intended by the ruling; it is a cost
  surprise, not a bug.
- **R-7 (provider-gating of the browser migration).** `RETIRED_MODELS` is keyed by model id only and
  applied before `validateSlot` (which re-derives the provider). A stored payload with a retired
  Gemini id next to `provider: 'anthropic'` would be rewritten to `gemini-3.8-flash`, fail
  `findModel('anthropic', ...)` and fall back by tier (P-9a, accepted as `gemini`-only). The outcome
  is a silent switch to Sonnet 5.5 for that slot; it is the accepted behaviour but untested today.
- **R-8 (absent level on a remapped slot; P-9b pinned to A).** Browser `validateSlot` and server
  `resolveSlot` both use `slot.level ?? model.defaultLevel`, which for `gemini-3.8-flash` is `high`, while
  the Fast default and `FALLBACK_FAST` use `low`. A stale Fast request or restored Fast slot with a retired
  id and no level therefore runs at `high`, not `low`: the approver pinned exactly that (option A), so it is
  intended and no code is added. It is still a silent cost difference against the Fast default, and a test
  that asserted `low` for such a slot would be wrong.
- **R-9 (`minimal` becomes unreachable).** After this Story no catalog model lists `minimal`. Every
  `minimal` level path (UI label entries, `extractFromPdf`'s `clampLevel(..., 'minimal')`) now resolves
  to `low` for every Gemini model. Not an error; the "leaves minimal untouched" provider test loses its
  subject (N-9, OD-8 ruling).
- **R-10 (CONTINUATION guard on a conforming SDK).** On 2.32.0 the guard is expected never to fire
  (Story Q8). If continuation is silently disabled or unsupported for a model, the failure is a thrown
  error naming the model (how `withRetry` classifies that error was not checked here); there is no
  test of the real SDK path (OD-5 waiver).
- **R-11 (usage across continued calls).** OD-6 is owner-stated and unverified. If it is wrong, the
  first hop's tokens are dropped and Carbon cost is under-reported with no error. FR-26 / FR-27 test
  prices only.
- **R-12 (lockfile churn).** A major SDK bump regenerates the `@google/genai` lock entry and may move
  transitive packages (the 2.32.0 manifest keeps the same four direct ranges, so the movement is
  expected to be small but is not verifiable here). It also changes what `npm ci` installs in CI.
- **R-13 (FR-30 scan keyed to four literal strings; plan review NB-3).** FR-30 names `gemini-3.7-flash`,
  `gemini-3.6-flash`, "Gemini 3.7 Flash" and "Gemini 3.6 Flash". Stale text that offers a retired model
  without any of them exists today: `.env.example` lines 33-36 ("3.7 and 3.6 Flash are still selectable",
  "3.7 and 3.6 Flash also minimal") and the `clampLevel` comment at `src/prompt-core/model-catalog.ts` line 115
  ("Flash 3.6 @ minimal"). A scan on the four strings passes before and after those edits, so it does not
  guard them; `test/active-docs-models.spec.ts` lines 24-26 are of that shape (they match only
  "Gemini 3.7 Flash on Fast"). Nothing errors; the stale text just stays.
- **R-14 (request-shape tests born green; plan review NB-2).** `clampLevel('gemini', unknownId, level)` falls
  back to `defaultModel('gemini')`, so a provider or `clampLevel` test fed a slot for `gemini-4-carbon` at
  `low/medium/high` is already green before the catalog contains Carbon (the fallback model, 3.1 Pro, has the
  same three levels). FR-20..FR-22 request-shape tests that do not first prove the id resolves through the
  catalog (`resolveSlot` returning `gemini-4-carbon`, or catalog membership) pass for the wrong reason.

## Blast-radius summary

US-11.1 is a catalog-plus-provider change, not a prompt or content change, and it reaches three
tracks. The shared `model-catalog.json` (read verbatim by the browser and the server) gains two
entries at positions that make **Carbon both `models[0]` and the first `premium` model**; that single
fact moves the Gemini Deep provider-switch pick, the server's unknown-model Deep fallback, `defaultModel`
and `clampLevel`'s unknown-id fallback from Gemini 3.1 Pro to Carbon, and is why the existing specs that
fail are a larger set than the retired-id list in the Specification's P-8 (add
`model-settings.image-blind.spec.ts`, the `defaultModel` / premium-fallback assertions in
`model-catalog.spec.ts`, `model-support.entries.spec.ts`, `model-support.image-blind.spec.ts`,
`llm-routes.spec.ts` and the Deep switch assertion in `model-settings.service.spec.ts`). The `balanced`
tier touches two type declarations and two component methods (the template does not change). The
service gains a restore migration, a persist-once rule and an OD-4 reading-2 branch. On the server,
`resolveSlot` gains a remap, `GeminiProvider#readText` gains a `CONTINUATION` throw, and
`pricing.js` loses two retired entries and gains a flat and a date-dependent one (watch the substring
loop). The riskiest line item is the `@google/genai` 1.x to 2.x major upgrade: it reaches Image Studio
(upload, count tokens, image generation) and the only real-SDK spec is
`classify-response.spec.ts`; with the live smoke waived and the SDK-internals notes in `gemini.js`
depending on 1.52.0 behaviour, the OD-1/OD-2 evidence step is the sole control. No FROZEN file, no
store, no locale list, no prompt, schema, renderer or validator and no corpus fixture is touched.
New component tests go to `npm run test:components`; all others to `npm run test:logic`. Specification
v2 adds one narrowing to this picture: FR-22's 65536 clause concerns the `generate()` path only, so
`analyzeImage` and `extractFromPdf` keep their caps and need no code change, but all three paths share
`#readText`, so the `CONTINUATION` guard reaches Image Studio's vision caption and PDF extraction too. P-9b = A
adds no code (`slot?.level ?? defaultLevel` already yields `high`); it adds only tests.
