## What the Specification asks for, in blast-radius terms

A client-led change (track `angular`) that also reaches the BFF, the usage price table and two shared contract files:

1. **New per-image actions** Upscale 4K and Variation on every generated image (image tile), each producing new versions in the same session (FR-1..FR-3). Upscale is a Pro-only 4K image-to-image edit; Variation re-sends `v{N}` plus the original prompt, K times.
2. **Several images per generation** (Images 1/2/4): N versions in one turn, each counted separately toward the 30-per-hour limit and toward cost, with a partial-success path (FR-4..FR-9). The layer that makes the N calls is unruled (OD-4).
3. **Product / Style ref role** per attached image, a Style-ref sentence in the request, a role tag in stored history, and a 5-image limit that now excludes the Style ref (FR-10..FR-14).
4. **Saved presets** in `localStorage` with delete (FR-15..FR-17).
5. **Money**: header "Today / month" spend from `GET /api/usage`, a pre-send estimate, one price table keyed by model and resolution as the single source of both the estimate and the recorded cost (FR-18..FR-22).
6. **Preservation and a11y** of everything US-10.1 and US-10.5 built (FR-23, FR-24), and UA/EN copy for all of it (FR-25).

No description prompt (Task A/B/C), `STORE_REGISTRY` value, `src/domain` schema, renderer, validator or generated HTML is reached. No FROZEN file is reached (see hazard 4).

## Silent-failure risks (produce no error, only wrong or vacuous output)

- **S1. Unknown request keys are stripped by the server.** `generateRequestSchema` is a default `z.object`; a client that sends an image count, a derived-action marker or a role to an unmodified server is not rejected: the field is dropped, one image is generated and billed once. Reached whenever B2 is skipped on the server-fan-out branch.
- **S2. Unknown response keys are stripped by the client.** `ImagesResponse` in `schemas.ts` is a default `z.object`. A server that reports "generated 2 of 4" or a failure count in a new field is parsed successfully and the field is gone; the warning of AC-4 is never shown and no test that checks only the images notices. Same risk for a per-image cost array.
- **S3. A Part-level role tag is forwarded to Gemini.** Parts are validated as `.passthrough()` on both sides and forwarded as stored; an unknown field can turn into a 400 from Gemini on every Style-ref request. A Turn-level tag is safe: `toResendTurn` projects history to `{id, role, parts}` and the server's `newTurnSchema` strips unknown keys. A mocked provider in a unit test sees nothing wrong.
- **S4. A 4K image priced at a 1K price.** If `price(model, count)` keeps its two-argument shape while the handler is changed to pass the resolution, or if the new table has a flat fallback entry, a 4K Upscale is recorded at the model's unit price with a 200 and no error. `image-model-consistency.spec.ts` checks only that price keys equal the catalogue ids, so a model-only entry still passes. The header totals (AC-12) then under-report with no signal.
- **S5. Estimate and recorded cost drift.** The price table is server-only (`pricing.js`); if the client estimate is built from a second copy, nothing but the new FR-21 equality test (over every catalogue pair) will catch a divergence. With rule A (no rounding) the floating-point sum of N per-image rows can differ from `unit * N` in the last bit (the Spec notes it); a test that compares sums would be flaky or wrong, one that compares per image would pass while a user-visible two-decimal figure disagrees.
- **S6. Spend counts the wrong rows or misses rows.** `mode` is `null` for Image Studio rows and `GET /api/usage` has no prefix filter, so selecting by `taskLabel` prefix has to happen after the rows are fetched (client) or in `server/index.js` (untested, hazard 7). A row selection by `mode IS NULL` alone could count text-generation rows (the Open Decisions log could not verify that the text write path leaves `mode` null; U-7). The month figure needs every row of the month, text rows included, so volume grows with usage and no requirement bounds it (Spec FR-18 planner note).
- **S7. The limiter counts the wrong unit.** One step per call versus per image (OD-4/OD-5), and whether a failed image counts (OD-5a: "a counted request is every one that reached the Gemini call"), decide whether an operator is locked out earlier than the number of images shown suggests. The limiter is in-memory per process and keyed by IP; a restart resets it.
- **S8. A user-preset id collides with a registry id.** `needsWhiteBackground` fires on `presetId === 'white-bg'`; a client-generated user preset id equal to a registry id (or the OD-12a pattern allowing it) would flatten backgrounds of results that were not "Product on white", with no error. The id also lands in `taskLabel`, so a `|` in an id would corrupt the label; the server pattern `^[a-z0-9][a-z0-9-]{0,63}$` rejects bad ids with a 400 (loud) but a colliding valid one passes.
- **S9. Preset storage placed in the wrong layer.** `localStorage` is a banned token in non-spec files under `src/utils/image-studio` (scan g, proven by `test/image-studio-architecture.spec.ts`). The scan only covers that directory, so a direct `localStorage` use in a service or component compiles and passes scans, but breaks NFR-14 (ambient effects through ports) and makes the preset tests unable to run with a fake. The failure is design drift, not an error.
- **S10. Upload count includes the Style-ref image.** `canAttachUpload(current.map(() => ({ kind: 'upload' })))` counts every attachment; unless the call site is changed (A11), the sixth attachment is refused with T-3 even though AC-8 allows five Product plus one Style ref. A role-change path (Style ref back to Product with five Product uploads attached) can reach six Product uploads with no check, which US-10.1 AC-3 forbids (Spec observation 7). Existing `upload-rules.spec.ts` stays green for either mistake because it tests the pure function, not the call site.
- **S11. Merged-turn history shape.** If each response is stored as its own model turn instead of one turn per user turn, history would hold consecutive model turns and the **next** send fails server `assertConsistent` with `INVALID_REQUEST` (400): the failure appears one message later, not at the Variation. A thought signature on a part must be echoed back exactly (US-10.1 FR-35).
- **S12. Announcements and focus.** `generation-runner.ts` computes the announced highest version number from a single response (`nextVersionNumber + created - 1`); with N calls or a merged response left on that code the T-17 text names the wrong version and no assertion that counts `role="status"` elements notices. The existing assertion "exactly one `role="status"`" stays green. Focus after Upscale/Variation (started from a button on an image) returns to the prompt field only by the existing in-progress-ends rule; no existing test starts an action from an image button.
- **S13. Cancel keeps nothing under a server fan-out.** `abortOnEarlyClose` aborts the controller when the **response** closes early; a server that fans out N calls therefore cannot return the partial results FR-9 (c) wants kept on Cancel, and a call that finishes after the abort writes no usage row (`if (signal.aborted) return;` before `insertUsage`), so a paid upstream response leaves no record. Under client fan-out each request is aborted individually. The Proposed text and the existing rule disagree until OD-4/OD-6 are ruled.
- **S14. Stale comments and counts.** `MAX_INPUT_REFS` rationale ("real maximum is 6: 5 uploads plus the attached version") becomes wrong with a Style ref (7); the ceiling of 10 still holds. The skill's "component runner has one file" is stale (17).
- **S15. Dashboard grouping.** User-preset ids add task labels to the dashboard's "By Task" view; no error, but the grouping widens.
- **S16. A scan can fire on a name.** `.env.example` must not define a variable whose name matches `/IMAGE|NANO|BANANA|STUDIO/i` (architecture scan c). If the opt-in live spec's gate variable is named after Image Studio and then added to `.env.example` to satisfy AGENTS.md section 6 item 7, that scan fails. `LIVE_DOC_TEST` is not listed in `.env.example` today.

## Blast-radius summary

The vendor facts (OD-1: 4K edit, candidate count) decide whether `server/providers/gemini.js` (not on the Story's surface) and `classify-response.js` change and whether AC-1 survives at all. No FROZEN file, no `STORE_REGISTRY` value, no description prompt, renderer, validator or corpus fixture is reached, and the uk-UA master direction is not involved; the only prompt-text risk is choosing a non-frozen home for the Style-ref sentence. The failures most likely to pass the gate unnoticed are the stripped-unknown-keys pair (S1/S2), a 4K image billed at a 1K price (S4), a Style-ref image counted in the five (S10), and a role tag placed on a Part (S3). About 27 source files and about 25 existing specs are touched or put at risk; the test helpers shared by roughly 30 specs are themselves affected. Because `server/index.js` and the `/api/usage` route have no spec, any server-side spend selection needs its own test seam.
