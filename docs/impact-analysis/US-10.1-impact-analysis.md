## What the Specification asks for, in blast-radius terms

A new `AppMode` value `'image-studio'` (FR-1); two image entries appended to the shared model catalogue (FR-2) with every text-model
path made to ignore them (FR-3, FR-4); a new image method on the Gemini provider and the client `LlmProvider` interface (FR-6); new
`/api/image-studio/*` BFF routes (upload, countTokens trim, generate) with their own body-limit middleware, per-IP rate limiter,
retry loop, response classifier, error taxonomy and per-image pricing (FR-5, FR-16, FR-25..FR-27, FR-39..FR-53, FR-60..FR-72);
a client chat UI with an IndexedDB session store, canvas re-encode, format conversion, ZIP/clipboard download, localisation and
live-region behaviour (FR-8..FR-15, FR-18..FR-24, FR-33..FR-38, FR-43..FR-50, FR-54..FR-59, FR-73..FR-86); a new prompt-text registry
`src/prompt-core/prompt-presets.ts` (FR-78..FR-80); and a build-scanning security spec (FR-65). It adds no generated product-description HTML.

## Silent-failure risks (things that break without an error)

1. **Route-level behaviour with no importable owner.** The middleware order of FR-27/FR-51 (CORS, then body limit, then `express.json`, then limiter) and `trust proxy` live in `server/index.js`, which no test can import. Unless the logic is moved into importable modules (the precedent is `server/cors-policy.js` and `server/llm-request.js`) or an Express app is booted in a test, a wrong order (e.g. rejections without CORS headers, so the browser cannot read the 413/429) passes the gate.
2. **Image entry leaking into a text path.** `defaultModel` is `models[0]`; the tier fallback is `find(tier)`; `deepModels`/`fastModels` list everything; `restore()` and `setDeepModel` accept any catalogue ID. Appending the image entries after the text entries keeps today's defaults, but a later re-order, or one missed path, silently offers or selects an image model for text work, or throws in `clampLevel` on a missing `levels`.
3. **Pricing silently wrong.** `getPrices` ends in a bidirectional substring loop and `FALLBACK_PRICE` (3.00/15.00 per M tokens). An image model ID that does not match an entry bills as a token-rated Sonnet-class call. The same ID string must be spelled identically in the catalogue, the pricing key, tests and fixtures; the IDs are unverified (V-3) and the $0.03/$0.06 prices are placeholders (V-5).
4. **Dashboard distortion.** Image rows carry `costUsd` per image with unrelated token counts; the dashboard's token-share cost `breakdown` bars and "by model" grouping mix them into the text-model picture. Accepted as additive by OD-35, but the effect on the existing totals/bars is visible and not otherwise guarded (no dashboard spec exists).
5. **Shared catalogue consumed by two runtimes.** `model-catalog.json` is read by the browser bundle and by Node. A shape the TS type does not model (entries without `levels`) is accepted by the `as ProviderSpec[]` cast, so the compiler will not flag a consumer that still assumes `levels` exists.
6. **`arch-guard` Rule #4 vs. test text.** A spec under `src/` that asserts the absence of the literal `GEMINI_API_KEY` (or any key name) would itself be reported by Rule #4, because the grep covers `src/**/*.ts` including specs and its exclusions are narrow. The FR-65 spec is under `test/`, outside that grep; client-side assertions of FR-5 ("no client string contains an environment-variable name") must avoid writing the literal in `src/`.
7. **Source-text pins in `app.component.template-wiring.spec.ts`** break on harmless re-flows of `TOOL_LABEL`, `TRANSLATIONS` and the `appMode()` chains, and the file forbids the word "consumables" in the template.
8. **Tests that prove less than they say.** Both runners lack a canvas and IndexedDB. Whatever is asserted for the EXIF removal (AC-5) and for atomic/eviction/quota behaviour (FR-44, FR-81, FR-86) is only as real as the injected seams (the Specification names a seam for the encoder, `window.alert`, the clock, `uiLanguage` and turn ids in NFR-14, but **not for IndexedDB**). The Spec already limits the AC-5 claim (proposed waiver W-2) and the AC-20 claim (W-1); the IndexedDB gap is not covered by a stated waiver.
9. **Pre-implementation checks are unguarded.** V-1..V-9 (live-API facts) are recorded in a human-authored, unregistered file; no mechanism checks it exists before IMPLEMENTATION (NFR-12). The spec's tests pin the recognizer, trim and size figures to results that are not yet known (V-2 for `FILE_MISSING`, V-3 for IDs, V-6 for sizes, V-9 for images-only turns).
10. **Quiet cost/quota divergence by design.** Counted requests and `usage_log` rows diverge (FR-66); the per-IP limiter is process memory, resets on deploy (accepted, FR-67). Not a defect, but the dashboard will not reconcile to the limiter.
11. **Existing generation paths sharing code with the image path.** `retryTransport` and `LlmService.post` are shared by every text call; any change there risks double-billing text calls or, if the exclusion is wrong, re-sending a paid image call.

## Blast-radius summary

US-10.1 is a mostly additive feature, but it crosses four seams that existing code shares with every text-generation path: the model
catalogue JSON (read by both the Angular bundle and Node, with several text-only helpers that assume `levels`), the Gemini provider and
the `LlmProvider` interface, `server/index.js` (the only wiring point, and not importable by tests), and `app.component.{ts,html}`
(a 1.5k-line component with `Record<AppMode, ...>` maps, `appMode()` chains and string-pinned wiring specs). It touches no STORE_REGISTRY
value, no store/locale path, no uk-UA master or Task C path, no HTML pipeline, no FROZEN file and no corpus fixture, so the
description-generation fan-out of this repository does not apply. The real work to plan is therefore (a) scoping every text-model path
to non-image catalogue entries without weakening the catalogue spec, (b) extracting the server routes/middleware/limiter into
importable modules so FR-27/51/66 can be tested, (c) a client IndexedDB session store and canvas/encoder seam that the available test
environments cannot exercise for real, (d) a new pricing path that must fail loudly, and (e) the first heavy component spec in the
`ng test` runner. New tests land in both runners (server logic and pure client logic in `test:logic`; the studio component and
the dashboard mixed-rows spec in `test:components`). Coverage floors apply to `src/prompt-core/prompt-presets.ts` and to any new
code placed under `src/utils/**`; `src/app/**`, `src/services/**` and `server/**` are outside the coverage include list.
