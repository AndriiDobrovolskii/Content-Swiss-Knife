## What the Specification asks for, in blast-radius terms

A pure Angular-track change to Image Studio plus three data-shape/data-registry edits:

1. Markup and styling of every studio surface (header, session list, results feed with turn cards, input thumbnails, image tiles, model text parts, compare slider in the full-view dialog, version strip placement, composer, empty state, progress indicator) onto the `--shell-*` tokens in two themes.
2. The stored session shape (`ports.ts` types, `schemas.ts` validation, the IndexedDB adapter, `apply-response`, the store) gains optional fields: per-turn `cost`, `durationMs`, `presetId`; an edit-source version; input-image references. Old sessions must still load; a present-but-invalid field is treated as absent (FR-23 Proposed, OD-28).
3. `PROMPT_PRESETS` (names of three presets, `lifestyle` ratio 4:3 to 4:5, new optional `description`) and the studio text dictionary (new, changed and plural-sensitive texts).
4. Behavioural departures the owner approved: native one-click download with no format selector, a timestamped archive name, the cost line and "New session" moved, the Generate label that follows the draft, and Ctrl+Enter.

No prompt, `src/domain` schema, renderer, validator, `STORE_REGISTRY` value, server route or generated HTML is reached. No FROZEN file is reached.

## Silent-failure risks (produce no error, only wrong or vacuous output)

- **S1. The IndexedDB adapter drops `Turn`-level fields, and no automated test can see it.** Now unconditional: the owner fixed `cost`, `durationMs` and `presetId` on `Turn` (OD-1, OD-3, Story AC-13a). `IndexedDbSessionStore.turnRecord()` writes only `{ sessionId, id, role, parts }`, and `loadSession()` rebuilds every turn as `parseStoredTurn({ id: row.id, role: row.role, parts: row.parts })`: a Turn-level field is lost on the first save and again on every load, so the summary line and the preset chip would silently never appear for real users. There is no spec for this adapter, `fakes.ts` records the human decision not to add `fake-indexeddb`, and the shared in-memory store clones whole objects, so every automated test passes. Fields on `Version` or `SessionMeta` survive (`meta` is stored whole).
- **S2. Thumbnail references.** The owner described them as "an array of indexes or ids of the attachments (`parts`)". Uploaded attachments are `fileData` parts whose bytes live in the `sentBytes` store keyed `(sessionId, fileUri)` (written best-effort: a store failure never blocks an attach, OD-37; deleted with the turn that is cut); an attached earlier version is an inline part inside the user turn. `remapFileUris()` (FILE_MISSING recovery) rewrites only `part.fileData.fileUri` and re-keys `sentBytes`: a reference stored as an index into `parts` is unaffected, one stored as a `fileUri` string would dangle after a recovery round and the thumbnail would just disappear (FR-3/FR-23 omit a dangling reference silently). The studio components have no reader for `sentBytes` today: `getSentBytes` is called only through the generation runner's deps (`image-studio.store.ts` L186, `generation-runner.ts` L188) and the adapter; the composer injects `SESSION_STORE_PORT` only for `putSentBytes`. Rendering an upload thumbnail in the feed needs a new read path through that port, per image.
- **S3. New `Turn` fields ride along in every generate request.** `buildGenerateRequest()` clones whole stored turns into `history`. The server strips unknown turn keys by zod default (from source) and `toContent` passes only `{ role, parts }` to the provider, so the model never sees a Turn-level field and nothing fails; the request just grows and the contract "a turn is the resend payload" is quietly widened, which FR-17 rule 5 and FR-23 forbid. A field placed INSIDE a part is different: `partSchema` is `.passthrough()` and `parts` go to the provider unchanged, so a Part-level field would reach the model API. `request-builder.spec.ts` L64 compares `request.history` to the stored turns with `toEqual`, so a spec seeded with plain turns stays green whichever way this goes.
- **S4. (settled as requirement, state-reach remains).** SQ-2-A fixes the three values (wire, recorded, check mark). The silent part left is state: `sameTurnContent()` compares `presetId` to decide `canRetry`, `execute()` re-sets the draft with `...draftSnapshot` (so `presetId` survives a send today), and `sendChip()` sets `presetId: null`. If the check mark and the wire id are split into two draft fields, the Retry comparison, the restore path and the new-session carry (`createSession` takes `carry` of `productName`, `aspectRatio`, `resolution` only) each decide which one is meant; a wrong choice changes the usage-database `taskLabel` or the recorded chip with no test failing except L128-141.
- **S5. Validation fails in both directions.** A strict zod field makes a session vanish from the list (P-9: `parseStoredSession` returns `null`, callers filter it out: not listed, not counted, not deleted), the opposite of FR-23. No validator at all (the three stored schemas are `.passthrough()`) lets a malformed `cost` or `durationMs` reach the display code and print `NaN` or `$0.00`, which FR-4 forbids. Old-session fixtures (`makeSession`) exercise only the "absent" case; the "present but invalid" table of FR-23 (OD-28 Proposed) needs its own seeded sessions.
- **S6. CSS-only requirements cannot regress in the unit runners.** Dark/light colours, `--shell-*` use, contrast 4.5:1, 1024 px width, truncation, slider drag, skeleton animation: Tailwind is the Play CDN loaded by `index.html`, not part of `ng test` (happy-dom has no layout engine), so FR-28..FR-30 are verifiable only by the FR-31 evidence artifact. A `slate-*` class left behind passes every test.
- **S7. Duplicated accessible names and `role` counts are decided by markup the runner cannot hide.** In `ng test` a Tailwind `hidden` does nothing; two copies of a control are both found. With Download/Edit on every tile AND in the dialog, a lookup that is not scoped to the dialog sees many buttons with the same name. FR-33 (exactly one `role="status"`) and FR-20 (progress without `role="status"`) are guarded by `image-studio.component.spec.ts` L95-103, which counts `[role="status"]` and `[aria-live="polite"]`; a progress element given `aria-live="polite"` would trip it, an `aria-busy` skeleton would not be counted at all. Under SQ-4-i the strip, and with it the dialog that the strip component renders today, would sit inside the `role="log"` container (`aria-live="off"`).

## Blast-radius summary

US-10.5 is confined to Image Studio, but it is wider than "restyle" suggests. It rewrites the markup of the container and all three child components, and it moves behaviour between them: the per-image Download and Edit actions, the single `role="dialog"` full view with its new compare slider, `busy` and the failure alert, and "Download all" all live today inside `StudioVersionStripComponent` as private state, while the ratified text places Download/Edit on feed tiles, "Download all" in the feed, the strip inside the `role="log"` container under the newest tile, and model text parts inside the turn card. It adds optional fields to the stored session shape, which fans out over `ports.ts` -> `schemas.ts` -> `apply-response.ts` -> the store -> `indexeddb-session-store.ts` and, if mishandled, onto the generate-request path through `request-builder.ts`. Presets and texts change in `prompt-presets.ts` and `studio-texts.ts` (two more places that have no plural or shared-literal support).
