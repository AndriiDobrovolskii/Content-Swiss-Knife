Three findings the human should read before approval (details in the log):
1. **OD-36 (eviction).** The premise that the session in use is the most recently active is false under the confirmed SD-32 (viewing is not activity; a send
   renews the stamp only at the commit). Read literally, B could delete the session the operator is leaving, the source of a model switch or a blocked-state
   exit, or a session whose paid response is still in flight. C-36.4 excludes them (the human's word "неактивну", the confirmed T-23 and AC-26 point there);
   the tie-break stays a proposal (P-2).
2. **OD-37 (quota on sent bytes).** The alert still fires. But the recovery the human describes ("add the image again") does not repair the session: the
   protected first turn keeps the dead `file_uri` and is resent on every send, so every later send meets `FILE_MISSING` and T-10 again; only a new session
   recovers (P-6). The combined effect with the confirmed SD-34 (a full store can also fail the commit of a paid generation) is disclosed.
3. **OD-39 (canvas).** Neither test runner has a working canvas (`happy-dom` has no adapter; no `canvas` package), so the gate can prove the plumbing of
   the EXIF removal through an injected encoder but not that a real canvas strips EXIF; that is a browser check (V-8). W-2 asks the human to accept that split.

**Re-open / new-decision triggers (a failed check raises a decision to the human or re-opens one as blocking):**
1. V-6 (ii) shows that content referenced by `file_uri` counts toward the vendor's request cap -> **OD-27 re-opens as blocking**.
2. V-6 (iii) shows a generated 4K version (resent inline) breaks the 7 MB figure or the 18 MB / 30 MB headroom (OD-23 C-23.7) -> a new decision.
3. V-7 shows `countTokens` unusable for image parts or a gap beyond the 20% margin -> OD-34 fallback / a new decision (OD-32 C-32.3).
4. **V-8 (new)** (ii) a target browser cannot encode WEBP, or (i) / (iii) EXIF / GPS survives or orientation is lost in a target browser -> a new decision (AC-5 cannot be met by the canvas there; a library or dev dependency is a human decision).
5. **V-9 (new)** the live API rejects a user turn that has only image parts -> a new decision about what an image-only message sends.
