## Findings (not decisions)

- **F-7 (AC-2 vs AC-1/AC-3).** If a collapsed group removes its items from the DOM, "the item of the active mode carries `aria-current`" cannot hold. Logged as OD-23.
- **F-8 (AC-3 vs the owner's earlier "state is persisted").** AC-3 persists only the rail; AC-1 persists nothing for groups. Logged as OD-24. The existing `seo_gen_*` storage reads are unguarded (only one `JSON.parse` has a try/catch), so there is no fallback precedent.
- **F-9 (AC-7).** "The improvement-request button" is a block of three elements (button, rename-editor pen, popup-blocked notice) in one `@if (feedbackUrl())`. v4 names only the button; the others follow it.
- **F-10 (AC-4d).** The old overlay offset (`top-[125px]`) was not the old header's height by any markup evidence (the old header holds a 13-button switcher; not measured). AC-4d's "no overlap, no gap" is therefore a deliberate change in geometry, not a preservation.
- **F-11 (AC-5).** v4 names the page background as `<body>` or `<main>`, but the opaque root wrapper div (line 1) sits between and `<main>` is translucent; the panel's surface is not named. OD-27.
- **F-12 (AC-6a).** Panel 384 px plus expanded rail 256 px leaves about 384 px at 1024 px, against 640 px today, with `overflow-hidden` on `body` and `<main>`. Panel-less modes gain width (768 px). Not measured. OD-29.
- **F-13 (AC-8).** Pinned `role=button` lookups (`getByRole('button', { name: /Image Tools/ })`, exact "Image Studio") require the rail items to remain buttons with unique names in both rail states; a rail built as `<aside>` also collides with the clear-all spec's `querySelector('aside')`. Selector updates are permitted by AC-8, but the Specification should say so.
