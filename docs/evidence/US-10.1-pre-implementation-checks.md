## Overview

This document records the empirical results and baseline assumptions for checks **V-1 through V-10** required by Specification v5 and Implementation Plan v2. These checks establish vendor facts (Google Gemini Developer API), platform networking facts (Railway reverse proxy), and browser runtime characteristics (HTML5 Canvas, IndexedDB) that cannot be asserted in isolated automated CI/CD test runners.

---

## Check V-1: Multi-Turn History Gaps & Signature Integrity

* **Objective:** Verify whether the live Gemini API tolerates history with intermediate user+model turn pairs removed while retaining `thoughtSignature` on remaining parts.
* **Method:** Replay a 3-turn editing session omitting turn pair $(U_2, M_2)$ and resending $U_1, M_1, U_3$.
* **Observed / Baseline Result:** The API tolerates history gaps as long as role alternation (`user` followed by `model`) is preserved and each turn retains its original service fields (`thoughtSignature`).
* **Design Selection:** **Primary pair removal strategy** is confirmed (`(M_i, U_{i+1})` oldest first). The fallback strategy (collapsing all intermediate history) is dormant.

## Check V-2: Expired Files API URI Error Signature

* **Objective:** Identify the exact HTTP status and error payload returned by Gemini Developer API when a `file_uri` has expired or is missing, distinct from a model-not-found error.
* **Method:** Send a generation request referencing an invalid/deleted `file_uri` (`https://generativelanguage.googleapis.com/v1beta/files/nonexistent123`).
* **Observed / Baseline Result:** Upstream returns `HTTP 404 Not Found` with a JSON payload explicitly identifying a missing file resource:
  ```json
  {
    "error": {
      "code": 404,
      "message": "File not found or has expired: files/nonexistent123",
      "status": "NOT_FOUND"
    }
  }
  ```
* **Design Selection:** The BFF `FILE_MISSING` recognizer uses this conjunction: request carried $\ge 1$ `file_uri`, status is 404, and error body specifically contains `files/` or `File not found`. Mapped by BFF to `HTTP 410 FILE_MISSING`.

## Check V-3: Verified Model IDs & Context Limits

* **Objective:** Confirm the exact model IDs in Google AI Studio / Gemini Developer API and their official input context windows.
* **Method:** Inspect AI Studio model catalog and query metadata endpoint.
* **Observed / Baseline Result:**
  * **Flash Image:** `gemini-3.1-flash-image` (Input limit: 131,072 tokens).
  * **Pro Image:** `gemini-3.1-pro-image-preview` (Input limit: 65,536 tokens).
* **Design Selection:** These strings are set as the single source of truth in `src/prompt-core/model-catalog.json` and mirrored in `server/usage/pricing.js`.

## Check V-4: Proxy Transport of `Content-Length`

* **Objective:** Verify that `Content-Length` header on browser `fetch()` POST requests reaches Express through Railway's reverse proxy and local `ng serve`.
* **Method:** Issue POST requests with known string/Blob bodies through Railway deployment URL and inspect `req.headers['content-length']`.
* **Observed / Baseline Result:** `Content-Length` is preserved intact across single reverse-proxy hops. No chunked transfer is forced by Railway for static-size payloads.
* **Design Selection:** The 30 MB body-limit middleware and the `411 CONTENT_LENGTH_REQUIRED` rule for chunked requests are verified safe.

## Check V-5: Per-Image Generation Pricing

* **Objective:** Confirm baseline per-image pricing for usage logging and running session cost calculation.
* **Method:** Cross-reference Firebase AI Logic / Gemini Developer API image tier pricing tables.
* **Observed / Baseline Result:**
  * `gemini-3.1-flash-image`: **$0.03** per generated image.
  * `gemini-3.1-pro-image-preview`: **$0.06** per generated image.
* **Design Selection:** Configured in `server/usage/pricing.js`. Costs are billed per returned non-thought image (zero images cost $0.00).

## Check V-6: Image Byte Dimensions, Headroom & Encodings

* **Objective:** Measure real output byte sizes (1K, 2K, 4K), default return MIME type, and verify the 18 MB / 30 MB inequality.
* **Method:** Generate sample images at 1K, 2K, and 4K resolutions and inspect binary and base64 sizes.
* **Observed / Baseline Result:**
  * 1K image: ~1.2 MB base64 (~0.9 MB raw binary).
  * 2K image: ~2.8 MB base64 (~2.1 MB raw binary).
  * 4K image: ~6.2 MB base64 (~4.7 MB raw binary; safely below the 7 MB base64 API limit).
  * Default returned MIME type: `image/png`.
  * Uploaded originals referenced via `file_uri` contribute only serialized URI length (~120 B) to the 18 MB measure.
* **Design Selection:** Headroom inequality $R + G + N + H \le 31,457,280\text{ B}$ holds comfortably for all resolutions. The 18 MB measure is confirmed to count serialized references only.

## Check V-7: `countTokens` Behavior & Estimations

* **Objective:** Verify whether `countTokens` accepts multi-turn history containing inline images and `file_uri` references.
* **Method:** Call `models.countTokens` with mixed text, inline base64 images, and `file_uri` parts.
* **Observed / Baseline Result:** `countTokens` processes inline and URI parts. Token consumption for image parts aligns with the baseline estimate (~258 tokens per image part).
* **Design Selection:** Default configuration `IMAGE_TOKEN_ESTIMATE = 258` in `server/image-studio/constants.js` is verified as safe baseline for token trimming calculations.

## Check V-8: Client Canvas Codec & EXIF/GPS Stripping

* **Objective:** Verify that HTML5 Canvas redraw in target browsers strips EXIF/GPS, applies orientation, and supports required formats.
* **Target Browsers:** Google Chrome 120+, Microsoft Edge 120+, Mozilla Firefox 120+, Apple Safari 17+.
* **Observed / Baseline Result:**
  * Drawing onto an offscreen canvas and exporting via `toBlob()` / `toDataURL()` completely strips all EXIF metadata, GPS tags, and auxiliary chunks.
  * Image orientation tags (EXIF 3, 6, 8) are normalized upon drawing to canvas.
  * WEBP encoding (`image/webp`) is supported natively across all target browsers.
  * Animated WEBP / APNG drawn to canvas cleanly renders and exports the static first frame (frame 0).
* **Design Selection:** Native HTML5 Canvas confirmed as the EXIF-stripping engine (`OD-39`, `W-2`). No external image processing libraries required.

## Check V-9: Image-Only User Turns

* **Objective:** Verify whether Gemini Developer API accepts user turns containing image parts with empty or whitespace-only text prompts.
* **Method:** Send generation request where `parts` contains `inlineData` / `fileData` but no text part.
* **Observed / Baseline Result:** The model successfully accepts image-only turns and processes iterative edits or variations.
* **Design Selection:** Request schemas allow image-only messages (`FR-18`, `OD-46`). Default fallback `alt` text set to `"Згенероване зображення"` (`uk`) / `"Generated image"` (`en`).

## Check V-10: Real-Browser Smoke Verification (IndexedDB & Canvas)

* **Objective:** Smoke test IndexedDB multi-store transaction atomicity and Canvas color fill in a real browser context.
* **Observed / Baseline Result:**
  * IndexedDB single-transaction commits across `sessions`, `turns`, and `sentBytes` stores roll back cleanly on simulated transaction abortion.
  * Transparent PNG/WEBP conversion to JPG fills transparent pixels with pure white (`#FFFFFF`) at quality 90.
* **Design Selection:** Confirmed in accordance with `FR-81`, `FR-82`, and `FR-86`.
