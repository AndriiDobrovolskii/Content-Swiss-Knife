# Vendor-facts evidence (US-10.6): Gemini image prices (T1 check 5, OD-2)

This file records ONE check: the published per-image prices of the two Gemini image models this Story bills. It is
the price half of task T1 (plan 9.1; Specification FR-22, NFR-7; Open Decision OD-2).

**Scope, stated plainly.** This file records T1 checks 1 to 5 of the plan (9.1), with the status of each: check 5 (published prices, E1) and checks 1 to 4 (live calls through the real route, E2 to E5, run on 2026-11-14). It is NOT the T40 live smoke: T40 proves the NEW server path after implementation; these checks ran against the EXISTING route on `main` (build `fde8c3a`), which already expresses each of them. Every result is stated for the model and resolution actually called; nothing is generalised past that.

**Who wrote this file and who ran the checks.** The orchestrating assistant (Claude Code, model claude-sonnet-5-5) ran the
price fetch and the live calls and composed the text, at the human's explicit instructions ("внеси ціни з сайту гугла в
evidence" and "запусти ці перевірки сам", 2026-11-14, user sbruhov@gmail.com; the human authorised the paid calls with
the key in the local `.env`). The human has not yet reviewed it. An earlier summary of the same page, produced by a `web-fetch`
sub-agent, agrees with the figures below; this file rests on the first-hand fetch, not on that summary.

## What this answers, and what it does not

- **OD-2, whether 1K and 2K differ for Pro.** Per the page they do not: one shared price, "$0.134 per 1K/2K image".
  For Flash they do differ (0.067 vs 0.101).
- **AC-14a ordering.** On these figures 4K is dearer than 1K for both models (Pro 0.24 > 0.134; Flash 0.151 > 0.067), so
  the Story's rule that a 4K image is not billed at a 1K price is satisfiable and testable.
- **The Pro model id.** The page lists `gemini-3-pro-image` and no `-preview` id (a search for
  `gemini-3-pro-image-preview` in the extracted text finds nothing). That is the id `server/usage/pricing.js` already
  uses. The older US-10.1 V-5 record (`docs/evidence/US-10.1-pre-implementation-checks.md`) names
  `gemini-3.1-pro-image-preview` at $0.06; the page does not list that id, so that record cannot be reconciled with the
  page and is not confirmed by it.
- **Current code versus the page.** `server/usage/pricing.js` `IMAGE_PRICES` holds flat `0.03` (Flash) and `0.06` (Pro)
  per image, resolution-blind (comment: "recorded 2026-11-01"). Both are below the page's lowest figure for the model
  (Flash 1K 0.067; Pro 1K/2K 0.134). Which numbers the product should bill (the published list prices, or something
  else) is the owner's ruling under OD-2; this file does not change the code and does not make that choice.
- **Input images are billed too.** The Pro entry states image input at $0.0011 per image (560 tokens). Upscale and
  Variation send an input image; whether the estimate and the recorded cost include input is not decided by the
  Specification (AC-13 and AC-14 speak of the price of the generated images). It is noted here for the owner and the
  planner, not decided.
- **OD-1.** (a) A 4K image-to-image edit on `gemini-3-pro-image` is accepted, with or without an instruction text (E2),
  so AC-1 is satisfiable. (b) One call cannot return several candidates on `gemini-3.1-flash-image` (E3); N images need N
  calls, which is the plan's default.
- **Merged turn, Style ref, concurrency.** Accepted on Flash 1K (E4, E5). Not tested on Pro or at 4K.
- **Not covered.** `gemini-3.1-flash-lite-image`, `gemini-nano-banana-2.1` and `gemini-2.5-flash-image` also appear on the
  page; they are not in the model catalogue this Story uses and are not recorded here. The Batch tab of other models was
  not examined. Not tested: a 4K version sent back as input (size bounds, E2 item 3); candidateCount on Pro; Pro with a
  merged turn or a Style ref; `imageCount` 2 through a NEW route (T40, after implementation).
- **Mutability.** Prices are a vendor's published list prices at the fetch time above; they can change. Re-fetch and compare
  the hash before relying on them at IMPLEMENTATION.

## Appendix B. The script

```js
// Live vendor checks for US-10.6 (T1 checks 1-4). Calls the REAL local route; never prints the API key.
import fs from 'node:fs';
const BASE = process.env.BASE || 'http://localhost:3011';
const OUT = process.env.OUT;
const FLASH = 'gemini-3.1-flash-image';
const PRO = 'gemini-3-pro-image';
const results = {};
let n = 0;
const id = () => `t${++n}`;

function dims(b64) {
  const b = Buffer.from(b64, 'base64');
  if (b[0] === 0x89 && b.toString('ascii', 1, 4) === 'PNG') return { w: b.readUInt32BE(16), h: b.readUInt32BE(20), bytes: b.length, fmt: 'png' };
  if (b[0] === 0xff && b[1] === 0xd8) {
    let i = 2;
    while (i < b.length) {
      if (b[i] !== 0xff) { i++; continue; }
      const m = b[i + 1];
      if (m >= 0xc0 && m <= 0xcf && ![0xc4, 0xc8, 0xcc].includes(m)) return { w: b.readUInt16BE(i + 7), h: b.readUInt16BE(i + 5), bytes: b.length, fmt: 'jpeg' };
      i += 2 + b.readUInt16BE(i + 2);
    }
  }
  return { bytes: b.length, fmt: 'unknown' };
}
function summarise(body) {
  if (!body || typeof body !== 'object') return body;
  const s = { ...body };
  if (Array.isArray(body.parts)) {
    s.parts = body.parts.map(p => {
      const o = { keys: Object.keys(p) };
      if (p.inlineData) o.image = { mimeType: p.inlineData.mimeType, ...dims(p.inlineData.data) };
      if (p.text !== undefined) o.text = String(p.text).slice(0, 200);
      if (p.thoughtSignature) o.thoughtSignature = `<${String(p.thoughtSignature).length} chars>`;
      if (p.thought) o.thought = true;
      return o;
    });
  }
  return s;
}
async function gen(label, req) {
  const t0 = Date.now();
  let status, body, raw;
  try {
    const r = await fetch(`${BASE}/api/image-studio/generate`, { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify(req) });
    status = r.status;
    raw = await r.text();
    try { body = JSON.parse(raw); } catch { body = { nonJson: raw.slice(0, 300) }; }
  } catch (e) { status = 'fetch-error'; body = { error: String(e.message) }; }
  const rec = { label, model: req.model, resolution: req.resolution, status, ms: Date.now() - t0, response: summarise(body) };
  results[label] = rec;
  fs.writeFileSync(OUT, JSON.stringify(results, null, 2));
  console.log(label, status, body?.kind ?? body?.error ?? '', Array.isArray(body?.parts) ? body.parts.length + ' parts' : '', body?.costUsd ?? '');
  return { status, body };
}
const imgPart = d => ({ inlineData: { mimeType: d.mimeType, data: d.data } });
const firstImage = body => body?.parts?.find(p => p.inlineData && !p.thought);

// C0: make a source image (Flash 1K)
const c0 = await gen('C0_source_flash_1K', { model: FLASH, aspectRatio: '1:1', resolution: '1K', history: [], newTurn: { id: id(), parts: [{ text: 'Studio product photo of a small matte white 3D-printed desk organizer on a plain white background.' }] } });
const src = firstImage(c0.body);
if (!src) { console.log('C0 produced no image; stopping'); process.exit(1); }
```
