# Evidence (US-11.1): `@google/genai@2.32.0` behaviour and the Gemini 4 vendor facts

This file answers two approver rulings recorded on the `HUMAN_SPEC_APPROVAL -> IMPACT_ANALYSIS` event in
`docs/workflow/history.jsonl`: (1) verify the installed `@google/genai@2.32.0`, including the three SDK-internal notes
in `server/providers/gemini.js`, before ARCHITECTURE_PLANNING is finished (OD-2, OD-3, OD-6); (2) record the vendor
facts from `ai.google.dev` before TEST_WRITING freezes the numbers (OD-1, OD-7). Part A is the SDK, Part B is the vendor.

(`npm install --package-lock-only --ignore-scripts`). `git status` of the repository's `package.json` and

**Who ran it.** The `so-planner` skill, run by the orchestrating assistant (Claude Code, model claude-sonnet-5-5), at the

### S8. Behaviour that is new in 2.x and is not in the repo's reliance list (OD-2 d)

1. **Method.** `grep -c` of tokens in the repo's `1.52.0` `dist/node/index.mjs` and in `2.32.0`.
2/3/4. As above.
5. **Raw output.** `createUndiciNoTimeoutDispatcher`: 0 in 1.52.0, 4 in 2.32.0; `headersTimeout`: 0 / 3; `createAttemptSignal`: 0 /
   2; `ContinuationTimeoutError`: 0 / 10; `X-Server-Timeout`: 1 / 2 (the header already existed in 1.52.0).
   Effect in 2.32.0 (`includeExtraHttpOptionsToRequestInit`): on Node, unless the caller supplies `httpOptions.fetch` or a
   `dispatcher`, every request gets a per-request undici dispatcher with `headersTimeout: 0` and `bodyTimeout: 0`, delegating to
   the global dispatcher. So undici's own 300 s header/body timeouts no longer end a long non-streaming call, and the SDK abort
   timer from `httpOptions.timeout` (`DEEP_TIMEOUT_MS` 1,200,000, `FAST_TIMEOUT_MS` 120,000) becomes the effective bound. The
   server-side `X-Server-Timeout` header (`ceil(timeout/1000)` seconds) is sent as before. `GeminiProvider` supplies no
   `fetch`, so the dispatcher applies. This is a behaviour change to record, not a break; `timeouts.js` stays verify-only
   (approver ruling). It touches no repo requirement.

  Default to 64K (65,536) output tokens."
- "Direct non-streaming REST calls (`generateContent`) on `gemini-4-carbon` and `gemini-4-argon`: Default to 32K (32,768) output
  tokens. Setting `max_output_tokens` greater than 32,768 on a non-streaming REST call to Carbon or Argon without a
  `continuation_token` returns a `400` error."
- table: "Google GenAI SDK, latest version | 64K | Yes, the SDK continues for you"; "Google GenAI SDK, older version, non-streaming |
  64K | No | Upgrade the SDK."
- "Automatic continuation needs these Google GenAI SDK versions or higher: ... JavaScript (`@google/genai`) 2.29.1 ... Earlier versions
  don't continue automatically. Output stops at 64K tokens."
- "If the model reaches the cap and has tokens left, the response ends with `finish_reason: CONTINUATION` and a `continuation_token`."
- "A hop spent entirely on thinking returns empty `text` with `finishReason: "CONTINUATION"`. Treat this as normal progress."
- "Timeouts: Timeouts and retries apply to each hop, not to the full run."
- Interactions-API guide (`long-decode`): "Client-side continuation requires Google GenAI SDK version ... 2.32.0+ for JavaScript";
  "Client `http_options` sets the HTTP timeout for each hop. Passing `timeout` to `interactions.create` caps total time across all hops."

Results. (OD-7) The 32,768 single-hop limit applies to Carbon (and Argon) and not to Hydrogen; Hydrogen is 64K per hop for streaming
and non-streaming alike; `maxOutputTokens` 65536 is valid for both: the owner's OD-7 statement is confirmed. (OD-3) Per hop:
confirmed by the vendor text and by S3. **Not confirmed:** the owner's Q7(b) ("on older versions a Carbon response stops at 32,768
tokens with `CONTINUATION`"). The vendor says an SDK call is 64K and the 32K cap belongs to a DIRECT REST call. **Residual risk
that only a live call settles (the live call is waived):** the SDK's `generateContent` is, on the wire, a non-streaming REST call;
the page does not say how the server tells an "SDK request" from a "direct REST call" (a header, a version string, or the
absence of a token). If the server treated the repo's call as direct REST, a Carbon request with `maxOutputTokens: 65536` and no
`continuation_token` would return HTTP 400 instead of continuing. The mitigations that exist: `2.32.0` continues automatically
if Google answers `CONTINUATION` with a token (S2); an HTTP 400 would surface as an `ApiError` with `status 400` and fail fast
in `withRetry`. No code in this Story's Surface can remove the residual; it is carried as a risk in the plan.

### V7. Usage across hops (OD-6; billing)

Verbatim (`long-decode?generate-content=true`, "Count tokens"): "With automatic continuation, `usage_metadata` reports the totals across
all hops. The SDK adds up every count field: `prompt_token_count`, `cached_content_token_count`, `candidates_token_count`,
`thoughts_token_count`, and `total_token_count`. `prompt_token_count` adds up the input tokens of every hop. Each hop sends your
prompt plus everything generated so far back to the model as input ... (with repeated hop inputs automatically discounted 95%
by implicit caching)." Table: "Google GenAI SDK, automatic continuation (the default) | Totals across all hops | Read the usage
fields as is." The JS field names in the guide: `usageMetadata.initialPromptTokenCount`, `promptTokenCount`,
`totalTokenCount`; the example response uses `promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`. Result: OD-6
(sum across hops, same names, no code change) is consistent with the vendor and with S3. **Not checked, and pre-existing:** the
fetched pages do not say whether `promptTokenCount` already includes `cachedContentTokenCount`. If it does (the usual Gemini API
shape), `GeminiProvider#usage` plus `computeCost` already bill cached tokens at both the input and the cache rate, for every
Gemini model, and hop-summing would enlarge the effect on continued calls. That is outside this Story.

### V8. Retired models

Verbatim (`models` page): "For any new projects, use our latest models: Gemini 4 Hydrogen or 3.5 ..."; `gemini-3.6-flash` still
appears in the `thinking` table with `minimal, low, medium, high`; the pricing page still lists `Gemini 3.8 Flash`. Nothing here
changes the Story's decision to retire 3.6 and 3.7 Flash in the product.

## Findings carried to the plan

1. `2.32.0` passes every SDK-internal note the repo encodes; no check failed, so nothing here widens the Surface.
2. The `retryOptions` comment in `server/providers/gemini.js` is partly stale (S5); update it inside the Surface.

### A.hop-check (hop-check.mjs)

```
// Usage: node hop-check.mjs <path-to-genai-index.mjs>
import { pathToFileURL } from 'node:url';
const sdk = await import(pathToFileURL(process.argv[2]).href);
const calls = [];
function mkFetch(responses) {
  let i = 0;
  return async (url, init) => {
    calls.push({ url: String(url), body: init.body && typeof init.body === 'string' ? JSON.parse(init.body) : null, hasSignal: !!init.signal });
    const r = responses[Math.min(i++, responses.length - 1)];
    return new Response(JSON.stringify(r), { status: 200, headers: { 'content-type': 'application/json' } });
  };
}
const hop1 = { candidates: [{ content: { role: 'model', parts: [{ text: 'AAA' }] }, finishReason: 'CONTINUATION', continuationToken: 'tok1' }],
  usageMetadata: { promptTokenCount: 100, candidatesTokenCount: 30, thoughtsTokenCount: 20, cachedContentTokenCount: 40, totalTokenCount: 150 } };
const hop2 = { candidates: [{ content: { role: 'model', parts: [{ text: 'BBB' }] }, finishReason: 'STOP' }],
  usageMetadata: { promptTokenCount: 130, candidatesTokenCount: 25, thoughtsTokenCount: 5, cachedContentTokenCount: 40, totalTokenCount: 160 } };
async function run(label, responses, cfgExtra = {}) {
  calls.length = 0;
  const ai = new sdk.GoogleGenAI({ apiKey: 'x', httpOptions: { timeout: 999999, fetch: mkFetch(responses) } });
  try {
    const r = await ai.models.generateContent({ model: 'gemini-4-carbon', contents: 'hi',
      config: { maxOutputTokens: 65536, httpOptions: { timeout: 120000 }, thinkingConfig: { thinkingLevel: 'low' }, systemInstruction: 'sys', ...cfgExtra } });
    console.log(label, JSON.stringify({ httpRequests: calls.length, text: r.candidates?.[0]?.content?.parts?.map(p=>p.text).join(''), finishReason: r.candidates?.[0]?.finishReason,
      usage: r.usageMetadata && { p: r.usageMetadata.promptTokenCount, c: r.usageMetadata.candidatesTokenCount, t: r.usageMetadata.thoughtsTokenCount, cache: r.usageMetadata.cachedContentTokenCount },
      reqBodies: calls.map(c => ({ cont: c.body?.continuationToken ?? c.body?.generationConfig?.continuationToken ?? null, keys: Object.keys(c.body||{}), thinking: c.body?.generationConfig?.thinkingConfig ?? c.body?.thinkingConfig, hasSignal: c.hasSignal })) }));
  } catch (e) { console.log(label, 'ERROR', e.name, e.message); }
}
console.log('SDK', (await import(pathToFileURL(process.argv[2]).href)).GoogleGenAI.name);
await run('two-hop', [hop1, hop2]);
await run('two-hop automaticContinuation=false', [hop1, hop2], { automaticContinuation: false });
await run('CONTINUATION no token', [{ ...hop1, candidates: [{ ...hop1.candidates[0], continuationToken: undefined }] }]);
await run('plain STOP', [hop2]);
```

### A.timeout-check (timeout-check.mjs)

```
import { pathToFileURL } from 'node:url';
const sdk = await import(pathToFileURL(process.argv[2]).href);
const hop1 = { candidates: [{ content: { role: 'model', parts: [{ text: 'A' }] }, finishReason: 'CONTINUATION', continuationToken: 't' }], usageMetadata: { promptTokenCount: 1 } };
const hop2 = { candidates: [{ content: { role: 'model', parts: [{ text: 'B' }] }, finishReason: 'STOP' }], usageMetadata: { promptTokenCount: 1 } };
let n = 0;
const fetchFn = (url, init) => new Promise((resolve, reject) => {
  const body = n++ === 0 ? hop1 : hop2;
  const t = setTimeout(() => resolve(new Response(JSON.stringify(body), { status: 200, headers: { 'content-type': 'application/json' } })), DELAY);
  init.signal?.addEventListener('abort', () => { clearTimeout(t); reject(Object.assign(new Error('aborted'), { name: 'AbortError' })); });
});
let DELAY = Number(process.argv[3]); const TIMEOUT = Number(process.argv[4]);
const ai = new sdk.GoogleGenAI({ apiKey: 'x', httpOptions: { fetch: fetchFn } });
const t0 = Date.now();
try {
  const r = await ai.models.generateContent({ model: 'm', contents: 'hi', config: { httpOptions: { timeout: TIMEOUT } } });
  console.log(`hop delay ${DELAY}ms, timeout ${TIMEOUT}ms -> OK after ${Date.now() - t0}ms, requests=${n}, finish=${r.candidates[0].finishReason}`);
} catch (e) { console.log(`hop delay ${DELAY}ms, timeout ${TIMEOUT}ms -> ${e.name}: ${e.message} after ${Date.now() - t0}ms, requests=${n}`); }
```
