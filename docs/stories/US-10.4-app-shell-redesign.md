# US-10.4 — Redesign the app shell

## Story

As a **content operator who switches between the app's tools all day**,
I want **a grouped, collapsible navigation and a restyled app layout following the new design**,
so that **I find a tool quickly, keep more screen space for the work, and see one consistent look in both light and dark themes**.

## Context

Part 1 of 3 of the Image Studio redesign (design: `Knowledge/Issues/5/Image Studio Redesign.html`, boards "Active session" and "Empty state"). The original single Story was split on 2026-11-08 by the requester's decision: **US-10.4** (this Story - app shell), **US-10.5** (Image Studio visuals, no new capabilities), **US-10.6** (new Image Studio capabilities). Suggested order: 10.4, then 10.5, then 10.6.

Decisions taken (2026-11-08): the new navigation applies to the whole app; both light and dark themes are kept; the light theme is derived from the same design tokens at the developer's discretion while meeting WCAG AA contrast; the mockup's "Suggest an improvement" link is **not** added as a new control. "Existing behaviour does not change" holds **except** for the intentional changes listed under "Product owner answers" below.

Layout decisions (second intake round, 2026-11-08): the new navigation is a global left rail only. The per-mode `w-96` input panel (`<aside>`) stays in the text modes, to the right of the rail. The dark-mode toggle becomes a moon/sun icon in the rail. The Image Studio's own saved-session count ("· history (N)") moves into the studio header (US-10.5; this is the studio's session list, not the generator History button). The minimum supported width is 1024 px (desktop-first; no mobile layout).

### Product owner answers (2026-11-08, chat) - revision v4

Source of every item below: the product owner's human answers, recorded in `docs/decisions/US-10.4-open-decisions.md` (v2, OD-1..OD-21) and summarised in `docs/evidence/US-10.4-clarification-report.md` (v2). Story v4 transcribes them and adds nothing the owner did not say.

- **Panel is not rendered in `image-studio`, `html-editor` and `dashboard`.** It is rendered in the nine text modes (including `generator` and `ua-generator` before any result exists, because the panel holds their Generate/Clear buttons) and in Image Tools. Removing the panel from `html-editor` and `dashboard` is the owner's removal of an old quirk ("no buttons there") and is an **intentional behaviour change**.
- **Clear All** is removed entirely from `image-studio`, `html-editor` and `dashboard`, because those modes no longer have a panel. The owner explicitly approves removing the Image Studio assertions from `src/app/app.component.clear-all.component.spec.ts`. No temporary or other header is created for Image Studio inside US-10.4. (This supersedes the interim answer that moved Clear All into an Image Studio header.)
- **History (clock) button and its overlay** stay exclusively in `generator` mode, in the header of the input panel. They are **not** added to any other mode (no new capabilities). The overlay is anchored to that same panel header (for example `top-[64px]`, or whatever the new panel header height is). (This supersedes the interim answers "History in all modes" and "History in the studio header".)
- **Improvement-request button** disappears from `image-studio`, `html-editor` and `dashboard` together with the panel; it keeps working in every mode that renders the panel.
- **Page background** `#0b1120` applies to the global `<body>` or the global wrapping `<main>`. The rail uses `#111a2e`. Mode interiors keep their `slate-*` colours within US-10.4.
- **Rail:** the bottom controls are, in order, Dashboard, Language, Theme, AI Settings. Expanded width 256 px (`w-64`), collapsed 64 px (`w-16`). Groups and rail are expanded by default. The rail collapse state is persisted in `localStorage` (example key `seo_gen_shell_rail_expanded`). Accessible names are translated per the localisation map. The order of items inside the groups stays as listed in AC-1. UA group names: "SEO та Текст", "Зображення", "Код".
- **Accent** `#7c3aed` is used only for active icons, borders and focus rings; text is high-contrast (for example white or light grey).
- **Verification:** visual and contrast criteria are verified manually and the result is recorded as an artifact (report/screenshot) under `docs/evidence/`. "No horizontal scrollbar at 1024 px" means no content is clipped off-screen so that it becomes unreachable.
- **Files:** the change may touch `index.html` (Tailwind), `src/app/types.ts`, create new components under `src/app/components/`, and update existing `*.spec.ts`. Old layout checks (for example the FAQ button in the same row as the UA button) count as a markup update and may be adapted to the new grouping.

Former open questions Q1 (History position) and Q2 (feedback button reachability) are answered above and removed from "Open questions".

## Acceptance criteria

Criteria marked **[AMENDED v4]** or **[NEW v4]** changed because of the product owner's answers above; unmarked criteria are unchanged from v3.

- **AC-1 [AMENDED v4]:** The left navigation groups the modes under three group headers with counts - "SEO & Text · 9", "Images · 2", "Code · 1" in the EN interface, and "SEO та Текст", "Зображення", "Код" (with the same counts) in the UA interface - where SEO & Text holds the nine text modes (generator, ua-generator, optimizer, translator, seo-generator, copywriter, readability, slug-generator, faq-generator), Images holds Image Tools and Image Studio, and Code holds the HTML editor. Items inside each group appear in the order listed here. Each group expands and collapses, and all groups are expanded by default.
- **AC-2:** The navigation item of the active mode carries `aria-current="page"`; no other item does.
- **AC-3 [AMENDED v4]:** A collapse control reduces the navigation to an icon-only rail and expands it back. The expanded rail is 256 px wide (`w-64`) and the collapsed rail 64 px wide (`w-16`). The rail is expanded by default; its collapse state is persisted in `localStorage` (example key `seo_gen_shell_rail_expanded`) and restored on reload. In the rail every icon control has an accessible name (for example "Image Studio"), and these names are translated in UA and EN per the app's localisation map.
- **AC-4 [AMENDED v4]:** After the redesign every mode reachable today (the 12 content modes and the Dashboard), the UA/EN language toggle and the AI model settings remain reachable, and selecting a mode shows the same main-area view it showed before. The only intentional difference is that `image-studio`, `html-editor` and `dashboard` no longer render the input panel and the controls it held (AC-4b, AC-4e, AC-7). The generator History button stays reachable (AC-4d).
- **AC-4a:** The dark-mode toggle is an icon button (moon in light theme, sun in dark theme) at the bottom of the navigation rail, with an accessible name, and it still switches the theme.
- **AC-4b [AMENDED v4]:** The per-mode input panel (`<aside>`) is rendered, to the right of the navigation rail, in each of the nine text modes (in `generator` and `ua-generator` including before any result exists) and in Image Tools. It is **not** rendered in `image-studio`, `html-editor` and `dashboard`. The old in-panel mode switcher is gone in every mode (the rail replaces it).
- **AC-4c [NEW v4]:** The bottom of the rail holds, in this order from top to bottom: Dashboard, Language toggle, Theme toggle, AI Settings. Each is reachable in both the expanded and the collapsed rail.
- **AC-4d [NEW v4]:** In `generator` mode the History (clock) button stays in the header of the input panel and still toggles the Generation History overlay. The overlay is anchored directly under that same panel header (no overlap with the header and no gap), whatever the new header height is. No History button is rendered in any other mode.
- **AC-4e [NEW v4]:** The "Clear All" button is not rendered in `image-studio`, `html-editor` and `dashboard`; in the other modes it is rendered and behaves as before. No header is added to Image Studio by this Story.
- **AC-5 [AMENDED v4]:** The shell renders in a dark theme matching the mockup - page background `#0b1120` (applied to the global `<body>` or the global wrapping `<main>`), navigation rail surface `#111a2e`, borders `#26324a`, accent `#7c3aed` - and in a light theme. The mode interiors keep their existing `slate-*` colours. The dark-mode toggle switches between the themes and no shell surface keeps dark colours in light mode.
- **AC-6 [AMENDED v4]:** Navigation and shell text meets WCAG 2.x AA contrast (4.5:1 for normal text) in both themes. The accent `#7c3aed` is used only for active icons, borders and focus rings, never as a text colour; text is high-contrast (for example white or light grey).
- **AC-6a [AMENDED v4]:** At a viewport width of 1024 px, in every mode, with the rail both expanded and collapsed, no content is clipped off-screen so that it becomes unreachable, and the navigation is fully usable.
- **AC-7 [AMENDED v4]:** The shell adds no new "Suggest an improvement" control. The existing improvement-request button (shown only when `environment.feedbackForm.baseUrl` is set) keeps working unchanged in every mode that renders the input panel, and is not rendered in `image-studio`, `html-editor` and `dashboard`.
- **AC-8 [AMENDED v4]:** The unit specs that pass on `main` before this Story still pass without their behavioural assertions being weakened. Permitted changes to existing `*.spec.ts` files are: selector or markup updates; adapting old layout checks (for example the FAQ-next-to-UA-button check) to the new grouping; and removing the Image Studio assertions of `src/app/app.component.clear-all.component.spec.ts`, which the product owner explicitly approved. The Image Tools assertions of that spec are kept. Each spec change is listed in the implementation report.
- **AC-9 [NEW v4]:** The result of the manual verification of AC-5, AC-6 and AC-6a is recorded as an artifact (report and/or screenshots) under `docs/evidence/`.

## Out of scope

- Redesigning the inside of any mode (inputs, outputs, editors) and Image Studio itself (US-10.5, US-10.6).
- New capabilities of any mode, including a History button in any mode other than `generator`.
- A header for Image Studio, and any Clear All, History or improvement-request control in Image Studio (the studio's own header is US-10.5).
- Recolouring the `slate-*` interiors of the existing modes.
- A "Suggest an improvement" feature.
- Prompts, FROZEN files, store profiles.

## Open questions

Not decided by the product owner; a specification writer would otherwise have to assume. `so-clarifier` formalises these (they overlap OD-19, OD-20, OD-21 in `docs/decisions/US-10.4-open-decisions.md`).

- **Q3:** What does the input-panel header contain once the language, settings, theme and Dashboard controls move to the rail, where does the app title/logo (`uiLabels().appTitle`, the cube icon) go, and what is the resulting panel header height that anchors the History overlay (AC-4d)?
  - Checked: `app.component.html` lines 8-45 (title, language, settings, theme, History, Dashboard in the panel header); the owner gave `top-[64px]` only as an example.
  - Impact if unresolved: the logo placement and the overlay offset would be guessed.

- **Q4:** In AC-2/AC-3, what does the rail show when the active mode's group is collapsed and in the icon-only rail; how are the groups represented in the icon-only rail; do group headers expose `aria-expanded`; and does the Dashboard item carry `aria-current="page"` when active?
  - Checked: AC-1 to AC-3; the owner's answers do not cover these.
  - Impact if unresolved: AC-2 ("exactly one `aria-current`") and AC-3 could contradict each other when a collapsed group hides the active item.

- **Q5:** Is the open/closed state of each group also persisted in `localStorage` (the owner said "state is persisted", the key example names only the rail), under which key(s), and what happens when `localStorage` is unavailable?
  - Checked: owner answers for OD-6 and OD-20; the app persists UI state under `seo_gen_*` keys.
  - Impact if unresolved: persistence of groups, key names and the storage-failure fallback would be guessed.

- **Q6:** Are the group counts static or derived from the mode list, and how is the count rendered next to the UA group names (the owner gave the names only)?
  - Checked: AC-1 (EN counts), owner's UA names.
  - Impact if unresolved: the UA count text format would be guessed.

- **Q7:** What are the exact EN and UA texts of the new accessible names (collapse/expand control, theme toggle, language, AI settings and Dashboard rail controls)? The owner said only that they are translated per the localisation map.
  - Checked: `TRANSLATIONS` en/uk maps in `src/app/app.component.ts`; existing specs pin some labels.
  - Impact if unresolved: product copy would be invented in the Specification.

- **Q8:** Which colours apply inside the input panel - its surface and header (shell tokens, per "rail and panel") versus the mode forms it contains (per-mode accents, "interiors keep slate-*")?
  - Checked: `app.component.html` panel form branches (lines 190-890); owner answers for OD-8 and OD-19.
  - Impact if unresolved: AC-5 cannot list the surfaces the manual check covers.

- **Q9:** What is the manual-verification matrix for AC-5, AC-6, AC-6a (who runs it, which browser, which modes, expanded/collapsed, light/dark), and is a main area of about 384 px (1024 - 256 expanded rail - 384 panel) acceptable at 1024 px, or must the rail collapse or the panel narrow?
  - Checked: owner answers for OD-10, OD-11, OD-21 give the meaning of AC-6a and the artifact location only; arithmetic from `w-96` panel and `w-64` rail.
  - Impact if unresolved: AC-9 cannot be reconciled against a defined matrix; a late Story amendment may be needed.
