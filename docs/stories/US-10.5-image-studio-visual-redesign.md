# US-10.5 — Image Studio visual redesign

## Story

As a **content operator who generates product visuals in Image Studio**,
I want **the studio screens restyled to the new design, with a before/after comparison of edits and a helpful empty state**,
so that **I can read the results feed at a glance, check what an edit changed, and start from a sensible template**, while everything Image Studio already does keeps working.

## Context

Part 2 of 3 of the Image Studio redesign (design: `Knowledge/Issues/5/Image Studio Redesign.html`). Follows US-10.4 (app shell); precedes US-10.6 (new capabilities). Image Studio shipped in US-10.1 and was hardened in US-10.2 and US-10.3.

Decisions taken (2026-11-08): this Story is **visual only**. The mockup's Upscale 4K, Variation, Alt text, Ctrl+K search, Today/month spend, Save-as-preset, Product / Style ref roles, Images 1/2/4 selector and pre-send estimate are **not rendered** here (the first two belong to US-10.6; Alt text and Ctrl+K search are dropped from the project for now). Existing behaviour does not change. Both themes are kept. All aspect ratios of the contract stay available. Quick-edit chips go directly above the prompt field; the version strip goes under the main generated image in the results feed. The starter cards update the `PROMPT_PRESETS` registry, which stays the single source of truth.

Second intake round (2026-11-08): the registry keeps **exactly five** presets so existing tests stay valid; three (white-bg, lifestyle, banner) are updated (name and ratio only - the prompt templates are **unchanged**) to match the cards "Product on white", "Lifestyle scene", "Category banner", and the other two (social, detail-closeup) stay as additional presets. Per-turn `cost`, `durationMs`, the preset used, the source version of an edit and the input-image references are added to the locally stored session history to feed the summary line, the chips and the thumbnails; sessions saved before this Story keep loading and simply hide what they lack. In Image Studio the per-mode input panel is not rendered (US-10.4): the composer holds every control. The session history count moves into the studio header. WCAG AA is the contrast standard; the minimum supported width is 1024 px.

Owner decisions of 2026-11-08 (answers to the Open Decisions of the clarification run; full record in `docs/decisions/US-10.5-open-decisions.md`): the download-format selector is removed (download is always the native format, one click); "Download all" names the archive `{timestamp}-{sessionName}.zip`; the Image Studio colours reuse the `--shell-*` tokens from US-10.4. The owner also ruled the Specification alternatives on 2026-11-08: an images-only send stays possible (the send button follows `canSend()`), the picked preset id keeps being sent as today, model text parts stay interleaved with the images, the feed keeps its log container, the delivery and archive tests are kept as native-delivery tests, `durationMs` ends at the hand-off to storing, and only a send with a version attached counts as an edit. These are small deliberate departures from "existing behaviour does not change" and are written into the criteria below.

## Acceptance criteria

### Header and session list

- **AC-1:** The studio header shows the title "Image Studio" and a "New session" button followed by the saved-session count ("· history (N)"). It does not show spend totals.
- **AC-2:** The session list shows "N sessions" (without a search hint); each row shows the session name (the last prompt entered in that session), its date as `dd.MM · HH:mm` (24-hour, local time) and its own session cost. The overall estimated-cost line (US-10.1 X-10) is no longer shown in the list.

### Results feed

- **AC-3:** Each generation turn shows its input image thumbnails, the prompt text, chips for the preset used (if any), aspect ratio, resolution and model, a summary line "N images · $cost · T s", and a "Reuse prompt" button. "Reuse prompt" puts that turn's prompt text, aspect ratio and model back into the composer and returns focus to the prompt field; it does **not** send a generation request. The preset chip and the thumbnails are read from the stored turn; a turn saved before this Story, which lacks them, shows neither without an error.
- **AC-4:** Each generated image shows its label `v{N} · {width}×{height}` and the actions "Download" and "Edit this →". "Edit this →" behaves as before (US-10.1 AC-22); "Download" saves the image in its native format in one click, and the download-format selector (US-10.1 X-7) is no longer rendered. `{width}×{height}` is computed at render time through the `ImageCodec.probe` port and is not stored. No "Upscale 4K", "Variation" or "Alt text" action is rendered.
- **AC-5:** A turn that edits an earlier version (a generation sent with a version attached through "Edit this →"; a quick-edit chip send or a typed follow-up stores no source version and shows neither control) shows an "Edit of v{N}" chip and a "Compare with v{N}" control that opens a before/after slider, inside the existing full-view dialog (not inline in the feed), labelled "Before (v{N})" and "After (v{M})". The slider is operable by keyboard and exposes `role="slider"`. The "Edit of v{N}" chip and the "Compare" control are read from the stored edit-source version; a turn without it (including every session saved before this Story) shows neither.
- **AC-6:** The results feed shows "Download all (N) .zip" where N equals the number of versions in the session (US-10.1 AC-35), and keeps the SynthID notice. The archive is named `{timestamp}-{sessionName}.zip`, where `{timestamp}` is UTC in the format `YYYYMMDD-HHMMSS` and `sessionName` is the session's last prompt, transliterated, with special characters and spaces replaced by hyphens (kebab-case) and capped at 40 characters; a name longer than 40 characters is cut before the last hyphen that lies within its first 41 characters, so that the result has at most 40 characters, or at 40 characters if there is no such hyphen (for example `20261108-181530-red-sneakers-on-white.zip`).
- **AC-7:** The version strip (US-10.1 AC-23) is displayed under the main generated image in the results feed; clicking a thumbnail still opens the full view.

### Composer

- **AC-8:** The preset row marks the selected preset with a check mark, which disappears as soon as the user edits the prompt text; no "Save current as preset" control is rendered.
- **AC-9:** The quick-edit chips (US-10.1 AC-18) are displayed directly above the prompt field, and only once the session holds at least one generated version (as today).
- **AC-10:** The aspect-ratio control offers every value of `image-studio-contract.json` (1:1, 4:3, 3:4, 4:5, 16:9, 9:16) in the existing native `<select>`; the resolution and model controls keep their current options and the rule that 4K needs the Pro model (US-10.1 AC-9). No "Images 1/2/4" selector, no Product / Style ref selector and no pre-send estimate is rendered.
- **AC-11:** The send button is labelled "Generate" (UA "Згенерувати"; US-10.1 X-1 was "Send") and shows the hint "Ctrl ↵"; Ctrl+Enter submits the prompt only when the button is enabled. The button is enabled exactly when `canSend()` is true, so a send with an empty prompt and a ready upload or an attached version still works as before; when there is nothing to send (empty prompt, no ready upload, no attached version) the button is disabled and reads "Write a prompt to start".

### Empty state

- **AC-12:** A session with no turns shows the headline "Your images will appear here", an explanatory sentence and three starter cards - "Product on white" (1:1), "Lifestyle scene" (4:5), "Category banner" (16:9) - each with its description. Choosing a card fills the prompt, aspect ratio, resolution and model exactly as selecting a preset does (US-10.1 AC-15) and leaves the prompt editable. The empty state is shown only while the session has no turns **and** no generation is in progress; during the first generation a progress indicator or skeleton is shown instead.
- **AC-13:** The three starter cards are read from `PROMPT_PRESETS`, not hard-coded in the component. The registry still holds exactly five presets (white-bg, lifestyle, banner, social, detail-closeup) and passes `validatePreset`; the `white-bg`, `lifestyle` and `banner` presets carry the card titles as names (UA and EN) and the card ratios 1:1, 4:5 and 16:9, and `lifestyle` defaults to 4:5 (was 4:3). The prompt templates of all five presets are unchanged. `PromptPreset` gains an optional `description`, which each card shows: white-bg "Perfect for e-commerce listings" / "Ідеально для товарних карток"; lifestyle "Product in a realistic setting" / "Товар у реалістичному оточенні"; banner "Wide format with space for text" / "Широкий формат із місцем для тексту".
- **AC-13a:** The stored session shape (and its `schemas.ts` validation) gains these fields, all optional on read: on the turn, `cost` (USD), `durationMs` (from the "Send" or "Retry" click to the moment the response is handed to the persistence port for storing; the storing itself and the attachment upload are not included, because a send cannot start while an upload runs) and `presetId`; the source version number of an edit (on the version or the turn - placement decided in ARCHITECTURE_PLANNING); and the references to the attachments the image was generated from, for the thumbnails of AC-3. The summary line of AC-3 renders cost and duration (in seconds). A session saved before this Story, whose turns lack these fields, still loads without an error; the summary line, preset chip, "Edit of" chip, "Compare" control and thumbnails are simply omitted for them.
- **AC-13b:** In Image Studio no per-mode input panel is rendered, and every control the user needs to generate (prompt, attachments, presets, ratio, resolution, model, Generate) is in the composer.

### Themes and preserved behaviour

- **AC-14:** Every Image Studio surface renders in the dark theme matching the mockup (page `#0b1120`, surface `#111a2e`, border `#26324a`, accent `#7c3aed`, reusing the existing `--shell-*` tokens from US-10.4 rather than `slate-*` classes) and in a light theme; no surface keeps dark colours in light mode, and text meets WCAG 2.x AA contrast (4.5:1 for normal text) in both. At a viewport width of 1024 px the studio shows no horizontal page scrollbar.
- **AC-15:** The Image Studio specs that pass on `main` before this Story still pass without their behavioural assertions being weakened; the only permitted test changes are selector or markup updates and the data changes this Story mandates - the three preset names, the lifestyle ratio 4:5, the "Generate" label, the removed download-format selector and the removed overall-cost line - and each is listed in the implementation report. The preset prompt-template assertions (`prompt-presets.spec.ts`) are not changed. Two further permitted changes, each listed in the implementation report: the dispositions of the Specification's table SQ-5 (the delivery and archive tests are kept as native-delivery tests and only the assertions that expected a converted entry change; the images-only-send tests change only their button lookup name), and the narrowing of the one assertion that counts generated images in the feed so that it selects the image tiles and not the version-strip thumbnails.
- **AC-16:** The studio still has exactly one `role="status"` element (US-10.1 AC-46) and focus remains in the prompt field after a generation finishes (US-10.1 AC-48).

## Out of scope

- The app shell and navigation (US-10.4).
- Upscale 4K, Variation, Images 1/2/4, Style ref, Save current as preset, Today/month spend, pre-send estimate (US-10.6).
- Ctrl+K session search and the "Alt text" action - dropped; not planned.
- Prompts (the preset prompt templates), FROZEN files, any server change.

## Open questions

Q1 ("Reuse prompt" restores prompt, ratio and model, no auto-send) and Q2 (the native `<select>` is kept) were answered by the owner on 2026-11-08 and are now written into AC-3 and AC-10.

Q3 (archive name: UTC `YYYYMMDD-HHMMSS`, 40-character cap, kebab-case) and Q4 ("Write a prompt to start" is the label of the disabled Generate button, AC-11; "Your images will appear here" is the empty-state headline, AC-12) were answered by the owner on 2026-11-08 and are now written into AC-6, AC-11 and AC-12.

Q5 (truncation rule for `sessionName` over 40 characters) was ruled by the owner on 2026-11-08 together with the Specification alternatives (keep 40 characters; cut before the last hyphen within the first 41 characters, else hard cut at 40) and is written into AC-6. No open question remains.
