# US-10.6 — Image Studio new capabilities

## Story

As a **content operator who generates product visuals in Image Studio**,
I want **to upscale a version to 4K, request variations, generate several images at once, mark an image as a style reference, save my own presets, and see what I spend before and after generating**,
so that **I get more usable visuals per session and keep control of cost**.

## Context

Part 3 of 3 of the Image Studio redesign (design: `Knowledge/Issues/5/Image Studio Redesign.html`). Builds on US-10.5 (the visual layer; these controls were deliberately not rendered there) and US-10.4. The Story is led from the client (`src/**`) but several capabilities need `server/image-studio/**` and `server/usage/**` work; per-task tracks are assigned by `so-implementation-planner`.

Decisions taken (2026-11-08):
- **Upscale 4K** is an image-to-image edit call to the Pro model: the chosen version is sent as the input image with resolution 4K; the result is a new version `v{N+1}` in the same session, billed as a 4K generation per the price table.
- **Variation** sends the chosen version `v{N}` back to the model as a reference together with the turn's original prompt; the number of results follows the "Images" selector; results become consecutive new versions.
- **Images 1/2/4** produces N images in one turn (default 1); the generator makes N parallel calls if the API limits a request to one image, otherwise one call; each successful image gets the next version number; each image counts separately toward the 30/hour limit and the cost scales by N; on partial failure the successful images are shown and only they are billed.
- **Style ref**: at most one per generation, not counted in the 5-image limit, sent with the instruction "Use this image purely as a stylistic reference, do not copy the product from it", stored in history with its role tag.
- **Saved presets** are kept in `localStorage` (no backend migration); the name is the user's own text (not localized) and a user preset can be deleted (trash or cross icon on hover).
- **Today / month spend** comes from the existing `GET /api/usage` (global, not the 7-day client cache), counting Image Studio rows only, with day and month boundaries in UTC. The price table gains a resolution dimension (4K costs more than 1K/2K). The **pre-send estimate** is computed on the client from the price table, resolution and N.
- Ctrl+K session search, the "Alt text" action and the "Suggest an improvement" link are **not** part of the project for now.

## Acceptance criteria

### Upscale and Variation

- **AC-1:** Each generated image has an "Upscale 4K" action. Running it on version `v{N}` creates a new version `v{N+1}` whose resolution label is 4K, and the usage record of that call carries resolution 4K and the model used.
- **AC-2:** Each generated image has a "Variation" action. Running it sends `v{N}` and the turn's original prompt, and with the Images selector at K the session gains K new consecutive versions.

### Several images per generation

- **AC-3:** Choosing N in the "Images" selector (1, 2 or 4; default 1) and pressing Generate adds N versions with consecutive numbers to the same turn.
- **AC-4:** Each generated image counts as one generation toward the 30-per-client-per-hour limit (US-10.1 AC-42): with 28 already used, requesting 4 images yields 2 images and the warning "Rate limit reached. Generated 2 of 4 images."; the request is not rejected as a whole and only the 2 generated images are billed.
- **AC-5:** When 2 of 4 requested images fail, the turn shows the 2 successful images and the recorded cost covers only those 2; the failure is shown, never silent.

### Style ref

- **AC-6:** Each attached image has a "Product" / "Style ref" selector; the default is Product.
- **AC-7:** At most one image can have the Style ref role per generation; marking a second is rejected with an explanatory message and the first stays marked.
- **AC-8:** A Style ref image does not count toward the 5-image limit (US-10.1 AC-3).
- **AC-9:** The request sent to the model contains the instruction "Use this image purely as a stylistic reference, do not copy the product from it" for the Style ref image, and the stored history keeps the role tag of that image.

### Saved presets

- **AC-10:** "+ Save current as preset" saves the current prompt, aspect ratio, resolution and model as a user preset under a name the user types (stored as typed, not localized); it appears in the preset row, survives a page reload (`localStorage`), and applies exactly like a registry preset when chosen (US-10.1 AC-15).
- **AC-10a:** A user preset has a delete control (trash or cross icon, visible on hover and on keyboard focus); deleting removes it from the row and from `localStorage`. Registry presets have no delete control.
- **AC-11:** Registry presets in `PROMPT_PRESETS` are unaffected by saving or deleting user presets.

### Spend

- **AC-12:** The studio header shows "Today $X · month $Y" where X and Y are the sums of the cost of Image Studio usage rows only (rows the usage store marks as Image Studio - today `taskLabel` starting with `image-studio|`, `mode` being null) returned by `GET /api/usage` for the current UTC day and the current UTC month. Text-generation rows are not included.
- **AC-13:** The pre-send estimate "≈ $X for N images" is shown next to Generate and equals the price-table cost of the selected model and resolution multiplied by N; it updates when the image count, resolution or model changes.
- **AC-14:** The estimate and the recorded cost use the same price table, so for one successful generation they are equal.
- **AC-14a:** The server price table prices an image by model and resolution; a 4K image costs more than the same model's 1K and 2K image, and an unknown model/resolution pair is rejected before any usage row is written (as an unknown model is today).

### Preserved behaviour

- **AC-15:** The pre-existing Image Studio specs pass without their behavioural assertions being weakened (US-10.1 AC-1 to AC-48 stay valid; AC-3 and AC-42 are amended only as AC-8 and AC-4 state).
- **AC-16:** Exactly one `role="status"` element remains and focus stays in the prompt field after a generation finishes (US-10.1 AC-46, AC-48).

## Out of scope

- Ctrl+K session search, the "Alt text" action, "Suggest an improvement".
- Server-side storage of presets; shared presets between people.
- Budget caps, per-user accounting.
- Visual layout of these controls (US-10.5 renders the surrounding UI).

## Open questions

- **Q1:** Does the Gemini image API accept an image-to-image edit with resolution 4K on the Pro model (the Upscale 4K decision), and does it accept several candidates per call? The requester decided on the edit call and on N parallel calls "if the API limits a request to one image".
  - Checked: US-10.1 allows 4K only on Pro (AC-9); no upscale code exists; US-10.3 holds the live-verification pattern for Gemini constants.
  - Impact if unresolved: the plan needs one live check before implementation (an opt-in live smoke as in US-10.3); if either assumption fails, AC-1 or AC-3 must be revised.

- **Q2:** What are the per-resolution prices? The requester said "for example 2x or 4x" for 4K; the current table is flat ($0.03 Flash, $0.06 Pro per image, source: V-5 of the US-10.1 evidence).
  - Checked: `server/usage/pricing.js` (`IMAGE_PRICES` keyed by model only); no source for resolution prices in the repository.
  - Impact if unresolved: AC-13/AC-14/AC-14a cannot name the numbers; they must come from the official Gemini pricing and be recorded as evidence.

- **Q3:** The usage store marks Image Studio rows by `taskLabel` (`image-studio|<preset>|<resolution>`) with `mode` null; the requester wrote `mode: 'image-studio'`. May the writer set `mode` for new rows, and how are existing rows (mode null) counted?
  - Checked: `server/image-studio/usage-row.js`; `GET /api/usage` filters only by `from`, `to`, `store`, `taskLabel`, `productName`.
  - Impact if unresolved: AC-12 uses the existing `taskLabel` marker; adding `mode` is a server schema choice.
