# Трекер запитів на автоматизацію

Канал, яким редактори повідомляють про рутину, що її варто автоматизувати:
кнопка **«Запропонувати покращення»** в застосунку → Google Form → таблиця зі статусами.

Форма створюється **один раз**, скриптом. Далі підтримки не потребує.

---

## Налаштування (≈5 хвилин, один раз)

### 1. Запустити скрипт

1. Відкрийте [script.google.com](https://script.google.com) → **New project**.
2. Вставте вміст [`create-form.gs`](./create-form.gs) замість того, що там є.
3. Задайте налаштування в **Project Settings → Script Properties** (не у файлі — див.
   [нижче](#налаштування-через-script-properties)). Усі чотири необов'язкові.
4. Виберіть функцію **`setUp`** у списку вгорі й натисніть **Run**.
5. Google попросить дозволи (створення форм, таблиць, надсилання пошти) — підтвердіть.
6. Перегляньте **Execution log**: якщо там рядки `!!! УВАГА: setRequireLogin(true)
   не спрацював`, форма лишилась відкритою для всіх — закрийте її вручну (див.
   [нижче](#доступ-до-форми)).

### 2. Перенести значення в застосунок

Скрипт друкує готовий блок в **Execution log**:

```
feedbackForm: {
  baseUrl: 'https://docs.google.com/forms/d/e/…/viewform',
  entryAuthor: 'entry.123456789',
  entryTool: 'entry.987654321',
},
```

Вставте його у `src/environments/environment.prod.ts` (і в `environment.ts`, якщо
хочете, щоб кнопка працювала і в `npm run dev`). Поки `baseUrl` порожній — кнопок у
застосунку немає взагалі, мертвого посилання команда не побачить.

Потім `npm run build` і деплой як зазвичай.

### 3. Додати питання для скріншотів (вручну)

Відкрийте форму → **Add question** → тип **File upload** → назвіть її
**«Скріншот (необов'язково)»** і залиште **не** обов'язковою.

Це єдиний крок, який скрипт зробити не може: у класі `Form` є `addTextItem`,
`addListItem`, `addImageItem` і решта, але **`addFileUploadItem` не існує** — Apps Script
уміє читати відповідь типу file-upload і не вміє створювати таке питання.

Заголовок має **починатися** зі слова «Скріншот» — саме за цим префіксом скрипт знаходить
колонку. Решту формулювання можна писати як завгодно.

Файли лягають у Drive власника форми. Доступ до них окремий від доступу до таблиці:
редактор із правами Viewer на таблицю побачить посилання, але не сам файл. Тому скріншоти
надсилаються в Telegram зображенням — там їх видно без жодних дозволів.

### 4. Дати команді доступ до таблиці

Відкрийте надруковану таблицю → **Share** → додайте редакторів із правами **Viewer**.

Це не формальність: саме видимий статус («Нове» → «В роботі» → «Зроблено») перетворює
форму з «чорної діри» на робочий інструмент. Без цього люди перестають писати.

## `setUp()` запускається РІВНО ОДИН РАЗ

`setUp()` не «оновлює» форму — він створює **нову з нуля**: `FormApp.create(...)`, нова таблиця,
нові `entry.*`. Усе, що ви додали руками — питання для скріншотів, будь-яке нове питання,
змінений тип відповіді — лишається у старій формі й у нову не переїжджає. Стара форма й таблиця
залишаються у Drive осиротілими, а посилання, яке ви вже давали редакторам, веде саме на неї.

Тому другий запуск зупиняється й нічого не робить. Якщо форма справді потрібна нова —
Script Properties → `FORCE_NEW_FORM` = `yes` (властивість зникає після запуску).

**Наявну форму правте в UI.** Скрипт цьому не заважає: назви колонок він шукає за заголовком,
а не за позицією, тож нова колонка в таблиці нічого не ламає. Нове питання автоматично
потрапляє і в лист, і в повідомлення в Telegram.

Одна річ, яку зміна в UI **може** зламати тихо: якщо поміняти **тип** питання «Хто подає запит?»
або «Де це трапилось?» (наприклад, з короткої відповіді на параграф), Forms замінює елемент і
видає йому новий `entry.*`. Кнопка в застосунку почне підставляти значення в неіснуюче поле —
без помилки, просто порожнім. Перевіряється це `printFormInfo()`.

---

## `printFormInfo()` — що зараз насправді у формі

Запустіть у редакторі Apps Script (Run → `printFormInfo`), далі **View → Execution log**.
Функція нічого не створює і не змінює, лише читає живу форму й друкує:

- назву, обидва URL і чи вимагає форма входу;
- усі питання з типами, у поточному порядку;
- **актуальні `entry.*`** для двох полів, які підставляє застосунок — звірте їх із
  `src/environments/environment*.ts`;
- чи є питання типу File upload і чи починається його заголовок зі слова «Скріншот»;
- заголовки колонок таблиці, з попередженням, якщо «Статус» або «Коментар розробника» зникли.

Потрібна властивість `FORM_URL` зі **URL редагування** форми (…/edit, не …/viewform).
`setUp()` записує її сам; для форми, створеної раніше, додайте вручну.

## Після кожного оновлення скрипта

**Файл у цьому репозиторії і проєкт на script.google.com — дві незалежні копії.** Правка
репозиторію не змінює нічого в живому скрипті, доки код не вставлено заново. Ми вже одного
разу на цьому спіткнулись: сповіщення «не працювало» рівно тому, що виконувалась стара копія.

Після вставлення нової версії:

1. Запустіть будь-яку функцію (зручно — `testTelegram`) і **прийміть новий запит на доступ**.
   Надсилання скріншотів використовує `DriveApp`, а це окремий OAuth-скоуп. Без повторної
   авторизації встановлений тригер почне падати з «Authorization required», причому мовчки
   для вас — лист про помилку йде власнику скрипта.
2. Надішліть тестову відповідь через форму і переконайтесь, що прийшли і лист, і повідомлення.

## Налаштування через Script Properties

**Цей репозиторій публічний.** Тому в `create-form.gs` немає жодного місця, куди можна
вписати значення — скрипт читає їх із Script Properties, які живуть у проєкті Apps Script
і в git не потрапляють ніколи.

**Ніколи не вставляйте токен бота у файл.** Комітований токен вважається скомпрометованим
з моменту пуша: його треба відкликати в @BotFather, а не «прибрати наступним комітом» —
в історії git він лишиться назавжди.

Apps Script → **Project Settings** → **Script Properties** → Add property:

| Property | Навіщо |
|---|---|
| `NOTIFY_EMAIL` | Куди слати лист про новий запит. Не задано → на пошту власника скрипта. |
| `FORM_URL` | URL **редагування** форми. `setUp()` записує сам; потрібен для `printFormInfo()`. |
| `FORCE_NEW_FORM` | `yes` — дозволити `setUp()` створити ще одну форму замість наявної. Видаляється після запуску. |
| `TELEGRAM_BOT_TOKEN` | Токен бота від [@BotFather](https://t.me/BotFather). Не задано → сповіщення в Telegram вимкнені, лишається тільки пошта. |
| `TELEGRAM_CHAT_ID` | ID чату або групи. Потрібен разом із токеном. |
| `TELEGRAM_TOPIC_ID` | ID гілки у форум-групі. Не задано → звичайне повідомлення в чат. |

## Доступ до форми

URL форми лежить у публічному репозиторії (`src/environments/environment*.ts`), тож сама
форма не має приймати анонімні відповіді — інакше надіслати запит у ваш трекер зможе будь-хто.

Скрипт викликає `form.setRequireLogin(true)`, що для Workspace-акаунта обмежує відповіді
вашою організацією. Для особистого Google-акаунта виклик не спрацює — і скрипт голосно
про це напише в лог.

**Форму, створену раніше, скрипт не перемкне** — він впливає лише на нові запуски.
Відкрийте форму → **Settings** → **Responses** → обмежте відповіді організацією
(або, якщо це не Workspace, увімкніть збір підтверджених адрес). Перевірити просто:
відкрийте посилання на форму в анонімному вікні — має вимагати входу.

## Що вийшло

**Форма** — 6 питань, заповнення до хвилини:

| Питання | Тип |
|---|---|
| Хто подає запит? | текст (підставляється застосунком) |
| Де це трапилось? | список інструментів (підставляється застосунком) |
| Що саме ви редагуєте? | текст: назва продукту / URL / ID |
| ДО — що ви отримуєте зараз | абзац |
| ПІСЛЯ — що має вийти | абзац |
| Наскільки часто це трапляється? | у кожному продукті / кілька разів на день / зрідка |
| Скріншот (необов'язково) | завантаження файлу — **додається вручну**, див. крок 3 |

**Таблиця** — усі відповіді плюс дві колонки для вас: **Статус** (випадний список
із кольорами) і **Коментар розробника**. Новий запит автоматично отримує статус «Нове».

**Лист** — повний текст запиту, як його ввели. Це архівна копія.

**Telegram** — навмисно не те саме. У чат іде сигнал «прийшов запит», а не сам запит:
хто, де, що, як часто, плюс перші 200 символів полів «ДО» та «ПІСЛЯ» **очищені від
HTML-розмітки**, і посилання на таблицю. Слідом — самі скріншоти зображеннями.

Причина конкретна: у поле «ДО» редактор вставляє HTML із застосунку, і це регулярно
20 000+ символів. `sendMessage` приймає максимум 4096, тож повний текст Telegram просто
відхиляв. Але навіть обрізаний він був би стіною розмітки — Telegram підтримує лише
вузький набір тегів, решта показалась би як `&lt;p style="margin:0 0 12px"&gt;`.
Оригінал із форматуванням лишається в таблиці та в листі.

## Якщо повідомлення в Telegram не приходить

Запустіть **`testTelegram`** у редакторі Apps Script (Run → обрати функцію → Run), потім
**View → Execution log**. Функція надсилає коротке тестове повідомлення й пише вердикт.

Якщо Telegram відмовив, у лозі буде повна відповідь API — читайте поле `description`,
воно називає причину дослівно:

| `description` | Що це означає |
|---|---|
| `chat not found` | Бота не додано до групи, або `TELEGRAM_CHAT_ID` не той. ID групи від'ємний, виду `-100…`; ID приватного чату — додатний. |
| `Unauthorized` | Невірний `TELEGRAM_BOT_TOKEN`. |
| `bot was blocked by the user` | Для приватного чату: спершу напишіть боту `/start`. |
| `message thread not found` | `TELEGRAM_TOPIC_ID` заданий, а в чаті немає гілок — приберіть властивість. |
| `message is too long` | Понад 4096 символів. Не має траплятись: у чат іде лише прев'ю. |
| `can't parse entities` | Зламана HTML-розмітка в повідомленні — це вже баг у скрипті, не в налаштуваннях. |

Порожній лог і жодного повідомлення означає, що блок навіть не запустився: не задані
`TELEGRAM_BOT_TOKEN` або `TELEGRAM_CHAT_ID`. `testTelegram` скаже, якого саме бракує.

Якщо не приходить **і лист, і повідомлення** — справа не в Telegram, а в тригері: перевірте
Apps Script → **Triggers**, там має бути `onFeedbackSubmit` на подію *On form submit*.

## Список інструментів

Варіанти питання «Де це трапилось?» (`TOOLS` у `create-form.gs`) мають збігатися з
`TOOL_LABEL` у `src/app/app.component.ts` — інакше Google Forms проігнорує підставлене
значення й редактор побачить порожній список. Додаєте новий інструмент у застосунок —
додайте варіант і у форму (правити можна прямо в UI форми, перестворювати не треба).

Списку **імен** ніде немає навмисно: ім'я — вільний текст, застосунок питає його раз
і зберігає в `localStorage`. Нового співробітника не треба вписувати в код.

## Текст анонсу для команди

> Дівчата, запускаємо офіційний трекер покращень для нашого HTML-редактора.
>
> Якщо ви ловите себе на думці, що робите одну й ту саму рутинну дію руками
> (форматуєте теги, міняєте посилання, видаляєте стилі) — **не терпіть це**.
>
> Внизу лівої панелі є кнопка 💡 **«Запропонувати покращення»**. У HTML-редакторі така
> сама кнопка є в панелі інструментів — вона ще й одразу кладе поточний HTML у буфер
> обміну, щоб ви просто вставили його в поле «ДО».
>
> Найважливіше у формі — приклад **«ДО»** і **«ПІСЛЯ»**. Одного речення «незручно
> працювати з таблицями» замало, а з конкретним фрагментом я одразу бачу, що робити.
>
> Я беру запити в роботу, а статус виконання ви завжди бачите у спільній таблиці: <посилання>.
